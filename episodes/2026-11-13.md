# N-central hotfix defeated as miners reach patched servers

*Fresh N-central exploits work against Hotfix 2, with production servers already compromised. ScreenConnect investigators identify a blank-key authentication flaw and confirm the technician-side patch works. Plus gateway wiping, GitHub secret theft and persistence that survives patching.*

Good morning, it's 5:22 AM. Friday, the thirteenth of November, twenty twenty-six.

Yesterday's N-central recovery ticket needs reopening. Two fresh exploit chains work against Hotfix 2, build 2026 point 4 point 1 point 26, and Huntback now counts at least twenty-one compromised production servers. Nineteen were on that latest build. They're running XMRig miners; I'd worry much more about who now owns the management server than the electricity bill.

Sean Bales published 4EverAble2Shell and Agent2Shell yesterday. The first enters through Apache Axis flaw CVE-2026-90436, running unauthenticated commands as the nable service account. A privileged helper and a symbolic link then make a root-owned script writable, and serverControl executes it as root. That route needs the Legacy API enabled. Agent2Shell reaches SYSTEM on managed Windows endpoints if the attacker knows the appliance ID.

For internet-exposed on-premises N-central, confirm Legacy API access is disabled, its default setting. N-able says hosted environments aren't affected by this issue; it's disabled the Intune integration and is restricting features while fixes are developed. Hotfix 2 isn't a clean bill of health. Hunt requests to /dms/services/ServerUI referencing jline.internal.TerminalLineSettings, and look for an unexpected xvd.service or files under /tmp/.xvd and /var/tmp/.xvd. Treat a hit as full server compromise.

There's a firmer answer on the other management-console incident, too. The ScreenConnect toolkit is now named SCKit, with sixteen components, and the count's reached two hundred and eighty-eight endpoints across forty-eight organisations. Huntress now points to RMM+ 1 point 0 point 31 and 1 point 0 point 32: if an administrator hadn't configured an access key, a blank one passed authentication. An empty key opening the door. That's painfully literal.

And there's welcome news about the technician trap: RelayTrap replaces the legitimate Guest process and attempts CVE-2026-84869 when someone connects. Huntress and Blackpoint say the fix in 26 point 6 point 5 blocks it, with no successful technician-workstation propagation observed. Make sure the technician clients are updated. That protects against this step, not the extension flaw; current server builds were among those breached.

Away from support consoles, PHP2Shell is now confirmed against Check Point Security Gateways through Mobile Access portals, in a separate campaign chaining a DynamicCLI escalation to root and progressing to ESXi and a wiper at Israeli organisations. Patch the gateway and PHP stack now; hunt zz*.tpl files and gateway SSH connections to ESXi as vpxuser. And stolen access is feeding wfx-loot on GitHub: four thousand eight hundred and thirty-seven hijacked accounts helped run a CI secret stealer in at least eighteen hundred and six repositories. Search for wfx-docs branches and pull requests titled “docs: dependency audit notes”; where it ran, rotate reachable workflow secrets and revoke the attacker's access, and treat machines that ran npm install on an affected commit as compromised.

On Windows, the public SignDrop proof of concept claims local SYSTEM through the Common Log File System driver's own anti-tamper feature; Microsoft hasn't confirmed it and there's no patch. Check Mode under HKLM\SYSTEM\CurrentControlSet\Services\CLFS\Authentication: zero or one means in scope, and watch for EDR self-protection tampering.

Back on exposed services, SANS now sees attempts against GPUStack, the GPU-cluster manager, spoofing X-Gpustack-Real-IP as 127.0.0.1 to bypass authentication. Upgrade to 2 point 2 point 0 and strip that header at the edge; the observed source is 144.91.73.103. But patching doesn't evict an established visitor: Microsoft sees attackers planting the legitimate GSocket remote-access tool on exploited Linux servers to survive the fix. Remove it and confirm relay connections stop, then audit persistence, including cron and systemd; the guidance also calls for patching CVE-2026-43284.

I'd establish N-central's exposure before accepting any completed patch ticket today. And where a management server's been compromised, I'd keep the investigation open beyond removal of the miner. Hope Friday leaves you a quiet weekend.
