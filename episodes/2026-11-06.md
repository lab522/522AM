# Long passwords, ineffective patches and cold-chain warnings

*An emergency OpenSSH fix closes a password bypass on Alpine and other musl-based Linux systems. Zyxel switches need replacement firmware despite earlier patching, while US agencies issue new guidance after refrigeration attacks.*

Good morning, it's 5:22 AM. Friday, the sixth of November, twenty twenty-six.

A password too long to hash can get you into an account that doesn't have a password. That's *sshole, disclosed by researcher Özgün Kültekin, and OpenSSH shipped emergency release 10.6p2 yesterday to fix it.

The conditions matter. It's musl-based Linux, including Alpine, running OpenSSH without PAM, with PasswordAuthentication yes. The target account's password field contains an asterisk, and another account has a dollar-five-dollar or dollar-six-dollar hash. Because that asterisk can't supply a salt, sshd borrows the other account's salt — behaviour introduced in twenty sixteen. Give musl a password between two hundred and fifty-seven and one thousand and twenty-four bytes, and crypt returns an asterisk on failure. It matches. A failed hash becomes a successful login.

On affected Alpine tiny-cloud images, the alpine account has passwordless doas, so that login reaches root. Glibc distributions and PAM setups aren't affected; no attacks have been reported. I'd patch this before coffee. Alpine has fixed packages back to 3.16: run apk upgrade -U -a, then rc-service sshd restart. The upgrade doesn't restart the daemon for you. If you can't update, set PasswordAuthentication no, validate with sshd -t and restart. Check /var/log/messages for Accepted password against accounts that have none.

And yesterday's Zyxel fix now has a crucial qualification: June's Patch 2 never stopped the attack. Binarly says the GS1900 campaign exploited a different flaw, CVE-2026-107441, which still isn't in KEV. The web handler copies an oversized parameter before checking its counter; by then, the attacker can redirect a function call and run commands as root without authentication. Binarly says reachability to the management service is enough. Patch 3 is out for ten models; on the GS1900-8, that's 2.90(AAHH.3)C0. Switches patched in June still need it. What bugs me here is that doing the prescribed work didn't buy protection. Check the actual model-specific build, not a completed patch ticket.

That gap between a closed ticket and a safe system matters rather more when the system controls a freezer. Five US agencies have now issued joint refrigeration guidance, calling the attacks an ongoing threat. The second European wave is now counted at more than a hundred and fifteen stores across six countries. Get controller panels off the public internet; necessary remote access should sit behind an updated firewall or edge device. Put controllers on a dedicated OT VLAN and replace default passwords. The guidance also calls for phishing-resistant MFA, retiring unsupported controllers and alerting on unsafe setpoint changes. Censys now counts three thousand one hundred and twenty-four exposed hosts, down from six thousand six hundred and ninety-five in October; that doesn't tell us why they disappeared. The Pentagon is reportedly investigating August freezer failures as a suspected cyberattack.

Back on hosting servers, XLab says a fake updater replaces Control Web Panel's cwpsrv binary with CWPdoor, awakened by an encrypted X-Ngx-Integrity-Data header; victims already exist. Check for the ngx_http_integrity_helper Unix socket or integrity strings in the binary; confirmed infections need a legitimate replacement and an upgrade, followed by credential rotation and a wider malware hunt. And for older intrusions, Cloudflare's Matthew Prince says PHP2Shell was probably exploited years before disclosure; Cloudflare is searching backwards through its logs. I'd extend affected management-interface investigations over months, rather than just the days around disclosure.

That longer view matters for quieter attacks too: Securelist describes Storm-2603 probing on-premises SharePoint on the twentieth of December, then returning on Christmas Eve with ToolShell code execution entirely inside the IIS worker process. Verify the existing ToolShell patches, correlate isolated probes with activity days later, and hunt in memory rather than relying on disk artefacts.

Holiday timing also features in CERT-In's new Crafty Falcon warning: the AI-assisted actor targets Indian financial businesses and has revisited victims after incomplete remediation, so separate test environments from production credentials and access, and keep monitoring staffed through holidays. Separately, sixty-two internet-facing ARTEX consoles served a backdoored build giving root access; tear down installations obtained from third-party Docker namespaces. On the defensive side of AI, Check Point found that another nested frame in ChatGPT's HTML preview could reach an unmodified popup function, escaping the sandbox and bypassing Lockdown Mode to steal chats silently. OpenAI fixed it server-side on the eighteenth of September; there's nothing for you to patch, but that hardening switch wasn't a reliable data-loss boundary.

And a final distinction between new danger and old paperwork: Mozilla's advisory replay has reached twenty ten, with thirty republished entries spanning MFSA 2010-57 through 2010-84, plus 2011-01 and 2011-02. Extend archive-date suppression back through that range; the exploitation language is historical, not evidence of attacks today.

I'd make sure an Alpine upgrade actually ends with the SSH daemon restarted. For the switch work, keep the ticket open until the installed firmware matches Patch 3 for that model. Hope Friday gives you a quiet finish.
