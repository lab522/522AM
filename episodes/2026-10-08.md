*Atlassian exploit attempts follow public research within two hours, while SonicWall issues another maximum-severity gateway fix. Also: a poetry-controlled mining botnet, hijacked domain registries, malicious npm packages and fresh details in the ShinyHunters investigation.*

Good morning, it's 5:22 AM. Thursday, the eighth of October, twenty twenty-six.

That Atlassian patch from Tuesday's show has become an emergency job. Previdian logged fifteen exploit attempts from three addresses within two hours of watchTowr publishing its research on CVE-2026-21589. SANS then saw the same exploit URLs coming from thirteen Digital Ocean addresses. These are honeypot observations, not a count of compromised customers, but the earlier reassurance about no exploitation evidence has been overtaken.

There's now a public Python proof of concept, and a Nuclei template makes scanning easy to automate. The revealing bit is how double colons become forward slashes in Atlassian's shared web-resource library, turning a resource request into file traversal. It can't escape the web application's directory or list its contents. Sounds limiting, until watchTowr reads crowd dot properties from Crowd-integrated Jira, retrieves plaintext credentials and uses them to add a Jira administrator. That's the difference between reading a file and owning the workflow.

Rapid7 now says patch outside the normal cycle. I'd take that advice, especially where Crowd supplies SSO. Apply Monday's fixed releases; if you can't, take the instance off the internet or use Atlassian's published filtering rules. Decode access logs up to twice and look for traversal sequences, including double colons. Rotate secrets from any files found to have been read. watchTowr also has a free scanner for checking instances.

And another edge system needs attention even if you patched it last month. SonicWall's SMA1000 remote-access gateways have a ten point zero pre-authentication SSRF in WorkPlace, their user portal. An alternate access path lets an outsider make the appliance issue requests on their behalf, reaching internal functions and performing unauthorised operations.

CVE-2026-102255 is the third maximum-severity, no-login WorkPlace SSRF fixed this year; the earlier rounds were exploited as zero-days. SonicWall says there's no evidence of exploitation this time. Small relief. September's fixes still need this hotfix: move the twelve point four branch to 12 point 4 point 3 dash 03670 or later, or the twelve point five branch to 12 point 5 point 0 dash 03082 or later, through MySonicWall. Installation restarts the appliance, and there's no listed workaround. The release also fixes authenticated flaws, including command injection. SMA 100 and firewall SSL-VPN aren't affected.

Those gateways aren't the only machines being recruited from the internet. Black Lotus Labs says PoeLLM has compromised more than three thousand four hundred servers since April, targeting exposed AI infrastructure and other services. Victims mine cryptocurrency, then become scanners and exploit launchpads themselves.

The command server's address comes from a poem on GitHub. The malware extracts four words and maps them to numbers using its own dictionary; changing the verse changes the destination without replacing the malware. Eleven edits so far. Clever indirection, and a thoroughly miserable use for poetry.

LiteLLM and Ollama deployments are among the targets; so are the Gotenberg PDF converter and self-hosted Git platform Gitea, along with Ivanti Sentry gateways. Infected hosts scan ports three thousand and four thousand, attempting a LiteLLM flaw that researchers say can be chained into unauthenticated code execution. Update affected services and restrict external access to trusted addresses. I'd check Black Lotus Labs' published indicators as well: closing the public door doesn't evict a miner already inside.

From a trusted host carrying instructions to trusted DNS carrying lies: attackers compromised the dot gh and dot sl registries, along with dot as, altered authoritative records and obtained unauthorised certificates for Google and others. The twelve identified Google certificates are revoked, but if you own names under those suffixes, check Certificate Transparency logs for unexpected issuance and monitor your whole portfolio, including parked domains.

Package trust took another knock: researchers linked eight malicious npm packages, with more than forty thousand downloads, to MALFEX, delivering Windows stealers and remote access malware. Check lockfiles and caches against the published package names—function-flag and function-color are still live—and treat machines that installed one as compromised, including rotating developer tokens.

And Tuesday's ShinyHunters arrests now have a named extortion target: Krebs identifies Jeppesen ForeFlight, Boeing's former aviation-navigation business, with sources warning of potential safety-sensitive data theft, although the company says it saw no impact. Malwarebytes also says the gang is bypassing Mandiant's suggested PeopleSoft firewall rules using URL encoding, so apply Oracle's fix for CVE-2026-35273 rather than relying on the rules.

Which makes a final finding particularly uncomfortable: ReversingLabs examined an unnamed shipping network appliance and found nine KEV-listed flaws, plus a cleartext private key shared across deployments. With the EU Cyber Resilience Act's exploited-vulnerability reporting duties already live, ask vendors for evidence from the actual shipped binary, tied to its version and hash—not just a compliance promise.

I'd get the emergency change owner involved now, rather than leave an urgent ticket waiting for someone to notice it. And give the log review an owner too; it shouldn't disappear behind a successful installation message. Hope Thursday treats you kindly.
