*Claude Code's saved permissions have exposed live secrets in public repositories. Arkéa clarifies the route into its banking network, IBM API Connect has seven critical flaws, and fresh findings widen the refrigeration attacks and expose unprotected ARTEX consoles.*

Good morning, it's 5:22 AM. Sunday, the eighth of November, twenty twenty-six.

Clicking “Yes, and don't ask again” shouldn't mean publishing your database password. But Apiiro has found secrets in eleven hundred and twenty-two public copies of Claude Code's local settings file on GitHub. One notified company confirmed its key was live. Whether anyone's used the exposed secrets isn't known.

Claude Code is Anthropic's command-line coding assistant. When you approve an exact shell command permanently, it saves an allow rule in .claude/settings.local.json. If that command contains a password, the password goes in too, in plain text. The assistant adds the file to your global Git excludes, but not the project's .gitignore. So the protection stays with your machine rather than travelling with the project. That's the bit that bugs me: something called local settings becomes shared configuration, with credentials attached.

Counting older versions and agent chat logs, Apiiro found more than two and a half thousand secrets across nearly two thousand repositories. And don't rely on a clean scan: neither Gitleaks nor TruffleHog flagged two hundred and fifteen of the affected local settings files.

If you use Claude Code in Git, search for .claude/settings.local.json and .claude/settings.json, including their history. Rotate exposed credentials first; deletion leaves history and forks intact. Remove the local file from tracking with git rm --cached .claude/settings.local.json, then add it to the project's .gitignore. Delete secret-bearing rules locally, too. Going forward, pass secrets through variables such as dollar DB underscore URL, and approve command patterns rather than exact commands containing credentials. I'd check this before approving another prompt.

Exposed credentials are one way across a trust boundary; a supplier platform is another. Following Thursday's Arkéa theft estimate, the French bank now says the attacker reached its network directly through a service provider's platform, and explicitly rules out Fortuneo. It won't confirm the hundred and eighteen million euro figure, only its order of magnitude, and says some funds were blocked.

Arkéa calls the incident closed and under control, says customer assets are untouched, and rules out human error. Funds were withdrawn as USDC and USDT; blockchain investigator ZachXBT says thirty million dollars had been laundered by the third of November. I'd keep supplier-platform access firmly inside the investigation boundary, whatever “closed” means for the bank. Arkéa's also warning customers about phishing: verify suspicious messages by calling your bank adviser directly.

From investigating access to preventing it: IBM API Connect, the platform enterprises put in front of their APIs, has seven critical flaws, scored nine point eight or nine point nine. Two need no login. CVE-2026-17408 passes insufficiently neutralised input into an operating-system command, potentially giving a remote attacker code execution on the host. The other pre-auth flaw gets to code execution through path traversal.

Affected releases are 10 point 0 point 8 point 0 through 10 point 0 point 8 point 12, and 12 point 1 point 0 point 0 through 12 point 1 point 1 point 2. The newer branch has all seven flaws; the older has five. The remaining bugs need an authenticated attacker, but still end in code or command execution. Exploitation isn't known. Get onto IBM's fixed builds; exact fixed version numbers aren't given here. Until then, keep management and gateway endpoints off the public internet, and review who has an API Connect login.

And exposed endpoints have consequences well beyond servers: the refrigeration attacks now span at least eleven European countries, while France's blood service says alarms and fail-safe measures prevented sample damage when cold rooms were heated on November the second. Russian hacktivists' claims remain unsupported by credible evidence, the Kremlin denies involvement, and operators should inventory connected devices and disconnect them where possible. Meanwhile, researchers have found hundreds of publicly accessible ARTEX AI hacking consoles that outsiders could use to attack other targets. If you deployed one to evaluate it, take it off the internet today and check whether any other hosts are serving it.

I'd put credential rotation ahead of repository tidying this morning. For API Connect, make verifying the fixed build part of the change ticket, not an assumption. Hope your Sunday gives you a decent stretch away from the keyboard.
