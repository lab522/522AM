# N-central's fourth hotfix, backdoored shops and an anonymous administrator

It's Tuesday, the eighth of September, twenty twenty-six. 522 AM is brought to you by Lab522, a technology partner for mid-market businesses, providing cyber security services and enterprise operational software. Email hello at lab522 dot co dot uk if you think we can help your business. N-able has shipped its fourth N-central hotfix in five weeks, and yes, even servers updated to Hotfix Three a day earlier need this one. N-central is the remote monitoring and management platform that lets an operations team reach across its managed estate. Code execution there isn't just somebody breaking into the tool cupboard. It's somebody getting access to the tools.

Every on-premises N-central build below 2026 point 3 point 1 point 14 needs Hotfix Four for an unauthenticated remote code execution flaw rated at maximum severity. There's an awkward split in N-able's own messaging: its incident notice says it's been exploited in the wild; its release notes say exploitation is unconfirmed. I'd treat the incident notice as the reason not to wait. Get onto that fixed build, and if you've already deployed Hotfix Three, don't let yesterday's completed change ticket send you back to sleep.

Staying with tools that reach other people's machines, attackers are abusing backdoored ScreenConnect instances to transfer and execute payloads on newly connected clients. ScreenConnect is ConnectWise's remote-access software, and here the useful feature — connecting a fresh machine for support — becomes the delivery route for a four-stage VBScript chain. If you operate ScreenConnect, check for unexpected client modifications and script execution around new connections. The important question isn't just who connected, but what arrived with them.

Separately, ConnectWise has warned of a new ScreenConnect Remote Access vulnerability with no patch yet. Temporary mitigations are available, and a fix is planned for later this week. Don't assume that flaw explains the malicious-client campaign; that link hasn't been established. Follow ConnectWise's mitigations while you wait for the patch.

From remote support to online shops: StyleSmuggler is being exploited against Magento and Adobe Commerce to execute code and plant a Linux backdoor. The warning covers all versions. That's a foothold on the server running the shop, not merely a page somebody's defaced, and a backdoor means fixing the original opening wouldn't necessarily evict the intruder.

Adobe's new Commerce template-engine vulnerability, CVE-2026-75650, scores ten: reachable over the network, no login and no click, with arbitrary code running as the application user. The affected releases include the August updates across the listed Commerce, Magento Open Source and Commerce B2B branches. There's no fixed release identified here. If you run these stores, get the current Adobe remediation guidance and investigate for compromise rather than treating this as a routine upgrade to schedule when trading's quiet.

And the other internet-facing systems actively changing hands are MikroTik routers. Attackers are chaining two recently disclosed RouterOS flaws to take control of devices with SSH exposed to the internet. The precise releases and fixes haven't been identified in this warning, but the exposure condition is clear. If you run RouterOS, check external SSH access now and restrict it to trusted management paths while you establish the applicable fixes. A router that belongs to someone else is a rather poor place to enforce your network boundary.

While we're on network kit, there are public exploits for two new D-Link DIR-822A flaws in firmware A underscore 101. The more urgent one, CVE-2026-86296, is a stack overflow in the DHCP client, scored ten and reachable over the network without a login or a click. The other affects its L2TP control-message parser and needs low privileges. Nobody's identified safe firmware here, so don't mistake a public exploit for a problem you can already close with an upgrade. Establish whether you have these devices and get D-Link's remediation position.

Right, that's the active attacks and exposed edge kit. The new flaw I'd give serious attention next is in 389 Directory Server, the LDAP directory behind Red Hat Directory Server. An attacker can become Directory Manager without knowing a valid password. Not steal the password. Not crack it. Become the administrator anyway.

Here's how: a failed SASL PLAIN bind as Directory Manager leaves a stale identity behind. A successful SASL ANONYMOUS bind on that same connection can then inherit it. The server effectively remembers who you claimed to be and forgets that you failed to prove it. CVE-2026-18922 scores nine point eight, works over the network without credentials or user interaction, and affects Red Hat Directory Server eleven and twelve. Directory Manager authority puts the directory's identities and configuration within reach. Exact fixed package versions haven't been given, so check Red Hat's advisory and keep LDAP access restricted to the systems that actually need it while you resolve the update.

Another administrative interface with rather too much power sits on Advantech's WISE-6610 industrial LoRaWAN gateways, which connect sensor networks to upstream applications. Two command-injection flaws affect listed WISE-6610, EL and P variants on firmware 1 point 2 point 1, build 20251110. Both need a low-privilege login, both work remotely without a click, and both have public exploits. Their score is nine point nine.

The mechanism is the interesting bit: an act argument becomes command injection in either the Basic Station certificate-deletion handler or the Node-RED library handler. So an account with limited access can reach command execution on the gateway. For the Node-RED flaw, CVE-2026-79698, upgrade to 1 point 2 point 4, build 20260821. That fix is explicitly identified for the Node-RED issue; don't assume it also closes the certificate-deletion flaw without confirmation. Keep those management interfaces on trusted administration networks.

There's also a ten-rated SAP flaw worth putting in front of your SAP team. A malformed Extended Passport Protocol header in a crafted network request can hit a memory-safety bug without authentication or user interaction. The named EPP processing releases are 7 point 22 EXT, 7 point 53, 8 point 04, and 9 point 18 through 9 point 20. The described outcome is undefined behaviour and abnormal termination, with potentially high confidentiality, integrity and availability impact — not a demonstrated code-execution chain. Check SAP's remediation guidance for those releases; a fixed version hasn't been named.

Which brings me to a code-execution chain that does have a public proof of concept. TantoSec has turned a padding oracle in Telerik UI for ASP.NET AJAX, the web-interface component library, into unauthenticated remote code execution. The catch matters: it only works against applications in a specific non-default configuration, and Progress patched the chain in July. If you own an application using Telerik, check that configuration and whether the July fixes actually reached production. The headline's broad; the exposure isn't.

Away from software flaws, Microsoft 365 attackers are getting plenty done by persuading people to let them in. One widespread theft-and-extortion cluster is targeting executives through fake IT help desk calls and adversary-in-the-middle token theft. Separately, the BigBear two point zero phishing service has bypassed MFA at two hundred and fifty-eight organisations and stolen more than five thousand Microsoft 365 credentials. These aren't grounds to write off MFA. They're grounds to check suspicious help desk calls alongside sign-in and session activity, rather than closing the investigation because an MFA challenge succeeded.

And stolen sessions aren't just a phishing problem. JSCeal malware can bypass Google authentication using stolen session cookies, alongside credential harvesting, surveillance and traffic interception. If you're investigating JSCeal on an endpoint, include the Google sessions it could have exposed. A password isn't the only thing that can carry access out of a machine.

One final pair of breaches shows how far sideways data can travel. Mathspace, the online maths-learning platform, says attackers stole data concerning more than a million students, staff and parents after breaching its internal Metabase reporting system. Metabase is a business-intelligence tool: the place you go to ask questions of your data. If you operate it, check who can reach it and what its connected data sources expose. The reporting layer can hold a much wider view than any single application screen.

And Trezor's August breach at shipping and logistics provider ShipMonk now affects eighty-one thousand customers, after another sixty-seven thousand US customers were added. That's a supplier breach, not evidence that the hardware wallets themselves were compromised. If you're affected, look for Trezor's updated notification rather than assuming the earlier customer count settled it.

I'd put N-central's fourth hotfix ahead of routine change work, and pair the Commerce response with a search for backdoors, not just a search for an update. Then check RouterOS SSH exposure and Directory Server reachability, and keep an eye on ConnectWise's promised fix later this week. 522 AM, brought to you by Lab522. Find us at lab522 dot co dot uk.
