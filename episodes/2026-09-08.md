Email us at hello at lab five twenty-two dot co dot uk if you think we can help your business. Adobe has released patches for the store takeover flaw we covered yesterday. That's the development Commerce and Magento operators needed: there's now a patch to apply, with attackers deploying a Rust backdoor and a PHP web shell.

The flaw, CVE-2026-75650, scores ten. It lets an attacker reach the template engine over the network, without a login or a click, and execute code as the application user. That puts them inside the software running your shop. A web shell gives them a way back in; updating the vulnerable code doesn't remove it.

For Adobe Commerce, affected releases span the 2 point 4 point 4 through 2 point 4 point 9 branches, including their August updates. For Magento Open Source, it's the 2 point 4 point 6 through 2 point 4 point 9 branches through August. Commerce B2B releases are also affected, so check that package against Adobe's advisory rather than treating the core update as the whole job. Apply Monday's vendor patches and investigate the store for those implants in parallel. Yesterday's uncertainty about a fix is gone. The need to establish whether somebody got there first isn't.

From compromised shops to compromised browsing: Cisco Talos has traced a ClearFake infection chain after spotting a DLL named verification.google executing from WebDAV at a Ukrainian government organisation. The chain delivers Amatera stealer, ZigCryptoStealer and NetSupport Manager, a legitimate remote-control tool being carried along with credential-stealing malware. That filename is doing some very optimistic public relations.

If you're investigating ClearFake activity, look for DLL execution from WebDAV and check for those payloads, not just the original browser interaction. The useful clue here is where the executable came from, not whether its name sounds reassuring.

And another Talos investigation puts the malicious code inside the browser session itself. A cryptocurrency-stealing ClickFix campaign uses the Google Visualization API to retrieve obfuscated JavaScript from a publicly published Google Sheets document, then injects it into the victim's browser session. Google-hosted infrastructure is supplying command and control. Clever, and awkward for defenders who treat a familiar domain as a clean bill of health. For these investigations, inspect the document access and script behaviour; the hostname alone won't separate ordinary spreadsheet use from this campaign.

Right, from attacks already happening to two new problems in SAP's internal plumbing. The nastier trust failure is in NetWeaver Message Server, the component coordinating application servers. CVE-2026-58240 lets an unauthenticated attacker with network access register an unauthorised component because the service doesn't adequately establish that it's a genuine internal application server. No click required, and it scores nine point eight.

That isn't a stolen user account. It's an outsider being accepted as part of the application environment, potentially gaining the ability to perform unauthorised actions there. Versions 9 point 18, 9 point 19 and 9 point 20 are affected. If you run them, check who can reach the registration service and restrict that path to the application servers that need it while you establish remediation with SAP.

The other SAP flaw is in the Extended Passport Protocol processing library, used to carry tracing context between components. Here, a malformed EPP header in a crafted network request reaches unsafe memory handling without authentication or user interaction. CVE-2026-44756 scores ten and affects 7 point 22 EXT, 7 point 53, 8 point 04, and 9 point 18 through 9 point 20.

The described outcome includes abnormal program termination, with potentially severe confidentiality and integrity impact too. That's serious, but it isn't a demonstrated remote shell, and I'd keep that distinction in the incident ticket. SAP hasn't identified safe releases for either flaw here. Map the affected components to your installations and check SAP's remediation guidance; for the EPP issue, exposure depends on the applications processing those headers, not merely whether a server carries an SAP label.

While we're on trust that hasn't been earned, Siemens Reyrolle 7SR5 devices have a session problem. These are protection relays used in electrical networks, so unauthorised access lands rather closer to physical operations than an ordinary office application. Their web interface exposes information that can be used to calculate current and past session IDs, letting an attacker bypass authentication.

CVE-2026-62645 scores nine point eight and is reachable over the network with no login or click. All versions before 2 point 70 are affected. If you operate these relays, arrange the move to 2 point 70 or later through your operational change process, and keep the web interface reachable only from authorised management systems in the meantime. A session ID that's calculable isn't much of a credential.

And there's a fresh reason to revisit the D-Link DIR-822A: a separate public exploit now targets an out-of-bounds write in its L2TP control-message parser on firmware A underscore 101. This one requires a low-privilege login over the network and scores nine point nine. Check CVE-2026-86510 with D-Link when assessing that firmware; the newly disclosed attack surface is L2TP handling, not the DHCP issue from yesterday.

Back in the browser, researchers have disclosed PEEP, a Chromium post-exploitation toolkit masquerading as a bookmarks extension in Chrome and Edge. The important word is post-exploitation: this isn't evidence that visiting a page can suddenly execute host commands. It's a way to turn a browser into a backdoor after compromise. If you're responding to an intrusion, include installed extensions and their provenance in the persistence review. A bookmarks label doesn't establish what an extension actually does.

And attackers are working on the route into the browser, too. BengalSEO is poisoning Bing search results to deliver MayaBot and tech-support scams. Discovered by the DFIR Report in March, the campaign makes malicious destinations look like answers to an ordinary search. When investigating a suspicious download or support call that began on Bing, preserve the search terms and redirect trail. The page the user eventually reached may only be the last stop.

One more, on the consequences of exposed data: a Vietnam-linked Advance Passenger Information System database held two hundred and twenty million passenger and crew records spanning twenty seventeen to twenty twenty-six. APIS handles passenger information for border processing, and the exposed fields included names, passport numbers, dates of birth, nationalities and flight details. Those are records, not necessarily that many distinct people. Even so, identity details tied to travel history are a particularly revealing combination.

And sensitive data doesn't have to be stolen to become a security story. Grindr has opted to pay twenty-six million pounds to settle UK claims alleging that it shared users' personal information, including HIV status, with third parties. That's a settlement over allegations, not a newly established breach. For teams responsible for analytics integrations, it's a pointed reason to inspect exactly which fields leave the application, not just whether the destination has an approved supplier record.

I'd use the first emergency change slot for Adobe's patches, with compromise checks running alongside the deployment.
