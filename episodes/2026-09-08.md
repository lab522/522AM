[serious] Adobe has released patches for StyleSmuggler. That's the important movement since yesterday: there's now a vendor fix for the flaw being used to backdoor online stores. The attacks include a Rust backdoor and a P-H-P web shell. [short pause] If you run Adobe Commerce or Magento Open Source, this deserves an emergency change, not a place behind the next storefront redesign.

The flaw, CVE-2026-75650, scores ten. Special elements aren't properly neutralised in the template engine, allowing code execution as the application user over the network, with no login and no click. Affected Commerce branches run from 2 point 4 point 4 through 2 point 4 point 9, including their August twenty twenty-six releases; Magento Open Source runs from 2 point 4 point 6 through 2 point 4 point 9. Commerce B-to-B releases are affected too. [calm] Apply Adobe's Monday security patches for your branch using its advisory. [serious] And with a web shell among the payloads, closing the entry point isn't the same as removing the visitor.

[short pause] There's also a useful new check for the N-central incident: administrators are being advised to look for newly created user accounts they don't recognise. N-central is the management platform with administrative reach into other machines, so an unexplained account there isn't a minor housekeeping problem. [confident] Add that check to the incident review, and investigate what any suspicious account accessed. That's today's follow-up to the hotfix work.

[pause] Meanwhile, a fake verification prompt has led to a rather different foothold. Cisco Talos began investigating ClearFake after seeing a D-L-L named “verification dot google” executing from WebDAV at a Ukrainian government organisation. The infection chain delivers Amatera stealer, ZigCryptoStealer and NetSupport Manager, a remote-control tool. [serious] For detection teams, execution from WebDAV is the useful behaviour to investigate; the reassuring filename is just the wrapping.

[curious] And another campaign takes ClickFix into the browser itself. Talos says cryptocurrency thieves are using the Google Visualization A-P-I for command and control, fetching obfuscated JavaScript from a publicly published Google Sheets document and injecting it into the victim's browser session. [short pause] Google's hosting the instructions, not endorsing them. If you're investigating suspicious browser activity around cryptocurrency use, examine what those Sheets requests returned and what script ran afterwards. A familiar destination doesn't make the content safe.

[long pause] Now to the new infrastructure flaws, and S-A-P has two that deserve attention together. The first lets a malformed Extended Passport header reach a memory-safety bug in its processing library. Extended Passport carries tracing context between S-A-P components, so this sits underneath applications rather than on a page somebody deliberately opens. CVE-2026-44756 scores ten: network access, no credentials, no user interaction. [serious] Abnormal termination is explicitly described; don't turn that into a claim of proven remote code execution.

The affected processing-library releases are 7 point 22 EXT, 7 point 53, 8 point 04, 9 point 18, 9 point 19 and 9 point 20. [short pause] The second flaw is a trust problem in NetWeaver Message Server, which coordinates application servers. CVE-2026-58240 lets an unauthenticated network attacker register an unauthorised component because registration doesn't sufficiently establish that the component is genuine. It scores nine point eight and affects 9 point 18, 9 point 19 and 9 point 20. An outsider presenting itself as part of the application environment—that's the bit I'd worry about. [calm] Safe builds haven't been specified here. Check S-A-P's security guidance for both, and restrict the affected services to the systems that actually need them.

[pause] From application infrastructure to electrical protection: Siemens Reyrolle 7SR5 protection relays have an authentication bypass with an unusually revealing mechanism. Their web interface exposes information that can be used to calculate current and past session identifiers. [serious] CVE-2026-62645 scores nine point eight, reachable over the network without credentials or user interaction. It gives an attacker unauthorised device access; the precise operations available aren't specified. [calm] Every version before V2 point 70 is affected, so move to V2 point 70 or later and keep that web interface confined to authorised management access.

[short pause] There's also a network-reachable deserialisation flaw in Hitachi Cosminexus Component Container, the Java application-server runtime beneath enterprise applications. CVE-2026-71374 scores nine point eight, with no login or click required. Multiple branches from nine through eleven are affected. [calm] For deployments from 11-70-01, the affected range stops before 11-70-03; for the 11-60 branch, it stops before 11-60-03. Check Hitachi's full branch matrix before choosing an update—several older branches have affected ranges listed without a safe destination. The disclosure doesn't describe a demonstrated payload, so don't assume a particular exploit chain.

And one more device flaw, distinct from yesterday's D-Link issue: the DIR-822A on firmware A underscore 101 has a public exploit for an out-of-bounds write in its L-two-T-P control-message parser. It requires a low-privilege login over the network and no user interaction. [serious] D-Link haven't identified safe firmware for this one. If you're running that build, restrict access to the affected service and check the vendor's remediation guidance; this is another attack surface, not merely another description of the same bug.

[long pause] Finally, an exposed passenger database brings the consequences back to people. A Vietnam-linked Advance Passenger Information System held two hundred and twenty million passenger and crew records, spanning twenty seventeen to twenty twenty-six. Names, passport numbers, dates of birth, nationalities and flight details were exposed. [serious] That's records, not a confirmed count of unique people. And travel history alongside passport details makes this much more sensitive than a mailing list. For teams operating passenger-data systems, review database exposure and access history; the news doesn't establish who accessed this one.

[short pause] Staying with sensitive data, Grindr has opted to pay twenty-six million pounds to settle U-K claims that it shared personal information, including H-I-V status, with third parties. These are allegations being settled, not an established finding described here. [serious] It's a different route to exposure: data leaving through a sharing arrangement rather than an attacker breaking in. For developers owning those integrations, what leaves the application deserves as much scrutiny as what gets in.

[confident] I'd put the Adobe emergency change first today, with a compromise review alongside it. Then I'd check reachability of those S-A-P services and Siemens relay interfaces, while watching the vendor guidance for exact remediation on the less complete disclosures.
