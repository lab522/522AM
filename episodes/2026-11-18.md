# Java4Shell puts the runtime on the emergency patch list

2026-11-18 · [listen](https://raw.githubusercontent.com/lab522/522AM/main/episodes/2026-11-18.mp3)

Brought to you by [Lab522](https://www.lab522.co.uk)

*Oracle has patched Java4Shell, a Base64 decoder flaw that researchers demonstrated could give unauthenticated attackers code execution in major enterprise applications. Optimizely's cleanup is complete, but the exposure review isn't; there are also management-plane fixes, an Uber supplier breach and another Mozilla advisory replay.*

Good morning, it's 5:22 AM. Wednesday, the eighteenth of November, twenty twenty-six.

Thursday's Apache warning now has company a layer down in the runtime. Different flaw, different fix: Java4Shell, CVE-2026-114938, lets malformed Base64 reach unauthenticated code execution in Java applications. Calif demonstrated it against default Keycloak and Jenkins installations, among other enterprise products. CISA wants Java users patching immediately. I'd make room for this one before the planned work.

The clever, nasty bit is the optimisation. Once decoding runs hot, HotSpot substitutes an accelerated routine whose padded-tail calculation reaches minus one. That opens the write mask fully and sends sixty-two bytes beyond the heap array. The trigger? Sixty-four A characters and an equals sign; on Java 17, a hundred and twenty-eight As instead. Basic authentication can feed the decoder before credentials are checked, so a login prompt isn't protection.

Exposure starts at OpenJDK 17 point 0 point 6, across the affected 17 and later branches, including downstream distributions, on x86-64 processors with AVX-512 VBMI. ARM is out, as are Java 11 and standard Java 8. Oracle's Tuesday fixes for those affected branches are 17 point 0 point 21 point 1, 21 point 0 point 13 point 1, 25 point 0 point 5 point 1 and 27 point 0 point 1 point 1. If you can't patch yet, start the JVM with -XX:-UseBASE64Intrinsics. Check inside container images: updating the host's JDK doesn't update theirs. There's a public reproducer, and GreyNoise is monitoring scanning and exploitation attempts; that's not confirmation of successful attacks.

From code beneath your application to code borrowed by your pages: there's better news on Optimizely. It's now publicly confirmed the incident and says remediation is complete, with added Cloudflare protections. Scott Helme says all infected files are clean. But the loader sat in the customer's Project JavaScript field and fired at page load, without waiting for consent.

The payload was rebuilt twenty-six times during the day; the crypto haul is now around seven thousand five hundred dollars. Thirty-two affected sites were finance or banking sites, and only twenty-four of the hundred and seventy-eight had a CSP that fully blocked it. That's the bit I'd take into the review, not just the cleanup notice. Reconstruct when affected pages ran the snippet; if it ran unblocked beside your own card form, count every card entered as exposed. A payment processor's hosted iframe was outside this skimmer's reach. Tighten the CSP rather than treating the vendor fix as the end.

The management-plane work isn't finished either: N-central's 2026 point 4 Hotfix 3 patches seventeen disclosed zero-days, and researcher Bales has published details of another twenty-four flaws he says are patched; hosted servers are updated, but on-premises servers need action. Upgrade Agents and Probes too—N-able warns that leaving them behind permits impersonation. And Puppet, the configuration-management system, has an actively exploited report-deserialisation flaw, CVE-2026-115731: any CA-signed agent certificate can get code running as the Puppet Server service user. Patch to 8 point 22 point 2 or 9 point 1 point 3, or the Enterprise fixes 2023 point 8 point 13 and 2025 point 12 point 1, and stop certificate autosigning; US federal agencies have until December first.

Valid credentials are also the uncomfortable detail at Uber: a supplier disclosed stolen credentials on October ninth, and attackers accessed supplier-specific cloud storage containing names and driving-licence data for nearly a hundred and fifty thousand people, without alerting Uber's cloud security team because the credentials were valid. For supplier cloud stores, limit credential scope and lifetime, and alert on bulk reads—not merely failed logins. Meanwhile, an alert that really does need suppression: Mozilla's replay now reaches MFSA 2007-32 through MFSA 2008-50. Extend archive-date suppression back to two thousand and seven and check for tickets opened overnight.

I'd reserve the first change window for affected Java runtimes, with the image owners involved from the outset. Keep the website exposure review open even though the injected files are gone. Hope your Wednesday leaves you time for a proper breakfast.
