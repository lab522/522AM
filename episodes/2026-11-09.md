# SSH scans climb, uploads execute, and clinic tokens linger

*SANS has fresh evidence of sshole exploitation attempts, while Contact Form 7 and OpenEMR need urgent updates. Also, an unsafe WordPress plugin, another Kyverno authorisation bypass, and a cloud breach affecting millions of shoppers.*

Good morning, it's 5:22 AM. Monday, the ninth of November, twenty twenty-six.

The SSH bypass we covered on Saturday now has numbers behind it. SANS Internet Storm Center's Cowrie honeypots caught the first genuine sshole attempt on November the fifth: a password made entirely of capital As. Over-long password submissions peaked at seven hundred and thirteen on the sixth, against fifty-eight two days earlier. Counts fell over the weekend, so that's a peak, not an uninterrupted climb. But Johannes Ullrich expects quite a few of those honeypot logins succeeded. That's his expectation; confirmation is still to come.

Cowrie only stores the first two hundred and fifty-five password characters, which limits the evidence, but oversized submissions stand out. And some broken brute-force scripts put post-login shell commands into the password field instead, including a wget command fetching a bot into slash tmp. Ullrich notes even those may have worked. A bot stumbling over its own script isn't much comfort if it still gets in.

SANS has also named scanning addresses across several networks; the busiest was 213.86.169.133, with forty-eight attempts. I'd finish Saturday's patch job before coffee, including the sshd restart. If that upgrade's blocked, disable password authentication and restart sshd. Then hunt for unusually long passwords where your telemetry records them, and accepted password logins on accounts meant to use keys only.

From passwords that shouldn't work to attachments that shouldn't run: Contact Form 7, the WordPress forms plugin, has an unauthenticated upload flaw rated nine point eight. CVE-2026-114432 affects versions from 6 point 2 before 6 point 2 point 4 when any form has a file field. The plugin doesn't validate file types or extensions, and broken temporary-file cleanup leaves the upload on disk.

The nasty part is what the web server does next. Stock Debian or Ubuntu Apache configurations list directory contents and send dot phar files to PHP, letting an attacker find the upload and execute code. On nginx, or Apache with dot htaccess overrides enabled, it's limited to an arbitrary file write, but HTML or SVG could still run as active content from your site's own origin. That's not a clean bill of health. Exploitation isn't known; update to 6 point 2 point 4 and inspect the uploads directory for unfamiliar files.

That same jump from application access to server access matters even more when the database holds health records. OpenEMR, the electronic health record and practice-management system used by clinics, has two critical flaws rated nine point nine before 8 point 3 point 0. Both need only a low-privilege login. In the fax and SMS module, an unchecked file_path parameter lets that user recover database credentials from sqlconf.php and write files as the web user, enabling code execution. Separately, the Fee Sheet drug-inventory lookup puts attacker-controlled input into an SQL ordering clause, allowing patient data and password hashes to be extracted through response timing.

But don't stop at 8 point 3 point 0. A separate flaw affects 7 point 0 point 1 through versions before 8 point 4 point 0: one-time authentication doesn't enforce its usage limits or revoke consumed tokens. Someone holding a captured token can replay it, or brute-force its PIN without rate limiting, to open patient-portal sessions. One-time in name only. Land on 8 point 4 point 0; exploitation isn't known. Until then, treat low-privilege accounts as capable of database access and code execution, and watch for repeated login_pin attempts against one service_auth token.

And another access boundary simply isn't there in WordPress's Userplace plugin through 1 point 2 point 0: an unauthenticated AJAX action exposes its protective nonce publicly, letting visitors create administrators or change site options. No fix is listed, so deactivate and delete it, then review administrator accounts and site options. Over in Kubernetes policy enforcement, a different Kyverno flaw lets tenants append malformed percent-escapes to an apiCall urlPath, escaping namespace restrictions to read other namespaces' resources and create mutating webhooks that lead to cluster admin. If you run 1 point 19 point 1, update to 1 point 19 point 2 and review who can create tenant Policy objects.

Away from patching, Japanese manufacturer Iris Ohyama says unauthorised access to a third-party cloud service may have exposed personal information on seven point seven million Iris Plaza shoppers; it suspended affected systems and notified Japan's privacy regulator and police on October the twenty-ninth. There were no reports of misuse or financial loss as of November the fifth, but affected shoppers should watch for phishing and change passwords reused elsewhere.

I'd check that completed change tickets actually include the service restart. And for clinic systems, make the target version explicit rather than leaving it at “upgrade OpenEMR”. Hope your Monday starts quietly.
