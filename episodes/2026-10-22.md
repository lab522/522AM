# PHP attacks predate disclosure; GitLab needs another patch

*PHP's emergency fixes are out, with AWS finding an exploit attempt four days before disclosure. GitLab needs another urgent update, while a poisoned LiteLLM release puts credentials at risk and Microsoft names the actor behind the ConnectWise compromise.*

Good morning, it's 5:22 AM. Thursday, the twenty-second of October, twenty twenty-six.

The PHP fixes landed yesterday, and the waiting-for-attacks part is over. AWS found an exploit attempt from the seventeenth of October, four days before disclosure, and says PHP2Shell is now broadly exploited. How that actor got the information is still unclear. The mechanism's public now: out-of-memory handling corrupts partially initialised memory, while stale state lets a worker reach memory freed after an earlier request. Together they allow code execution as the web worker, or theft of secrets from its memory. Apache mod_php is the highest-risk deployment: the attack gets in before application code runs.

Update the PHP runtime to 8 point 5 point 12, 8 point 4 point 27, 8 point 3 point 36 or 8 point 2 point 35, then restart the services and long-running workers. Updating WordPress doesn't do that job. Distribution packages may carry backported fixes; check their changelog. Source backports cover 7 point 4, 8 point 0 and 8 point 1; otherwise get a vendor fix or disconnect. I'd also look backwards, particularly for unusual multipart requests followed by memory-limit errors or repeated HTTP five-hundreds. Hundreds of sites were pulled offline as a precaution. Cortex Xpanse counts over twenty-two point six million exposed instances; Talos reckons roughly half the vulnerable systems will never be patched. And PHP blames Chainguard for shipping fixed images six hours early; its chief executive says attacks were already happening and he'd do it again. That argument won't repair a server.

Nor does last week's patch settle the GitLab job. There's a different integer overflow in its Onigmo regular-expression compiler, reaching self-managed CE and EE all the way back to 7 point 0. CVE-2026-110264 scores ten and can allow unauthenticated code execution under conditions GitLab hasn't spelled out. That's the frustrating bit: you can't confidently rule yourself out by configuration. No workaround, no public proof of concept, and no known attacks. The fixed releases are 19 point 5 point 1, 19 point 4 point 3, 19 point 3 point 6, 19 point 2 point 9, 19 point 1 point 9, 19 point 0 point 10 and 18 point 11 point 13. Single-node upgrades to the fixed 19 point 4 and 19 point 3 releases need downtime for database changes; GitLab.com is already covered.

Another server worth moving up the queue: Cisco's Expressway communications gateway has an unauthenticated database-service flaw giving attackers root, alongside information-disclosure and hardening fixes. Follow Cisco's first-fixed-release table; there's no workaround, and older trains need migration. But for LiteLLM, the AI model proxy, the new release was the danger: 1 point 107 point 0 on PyPI and Docker carried a credential stealer and a daemon fetching Python to execute, after stolen GitHub CLI OAuth tokens compromised release approvals. Pin 1 point 106 point 2 by digest, and rotate every secret reachable from affected hosts using a clean machine.

That trusted-supplier problem has a new attribution at ConnectWise: Microsoft names China-state aligned Storm-0940, using the agentic pentest framework ARTEX against more than two thousand two hundred and fifty tenants, with privileged cloud access achieved in under three hours in several attacks. Phased restoration began Wednesday; keep connections disabled until restoration instructions arrive, and review service-principal sign-ins for unexpected credential or privilege changes.

Credentials were also being caught on the wire: attackers used Ebury-compromised servers to hijack more than three hundred Tor exit relays in early October, redirecting SSH through password-interception servers. If you accepted an unfamiliar or changed host key over Tor during that window, change the password and check the destination server for Ebury; key-based authentication isn't relayable this way. Back on the endpoint, Chrome 156 brings three hundred and fifty-three security fixes, six critical, with no exploitation mentioned by Google. Push it out and get browsers restarted; an update waiting for a restart isn't finished.

And a browser restart won't resolve the disruption at Onamae Desktop Cloud, GMO Internet's Japanese VPS service: attackers installed malware on up to twenty-six thousand seven hundred and thirty-nine customer servers, with shutdowns under way across all plans and no restart date. Treat stored secrets as compromised and rotate them; GMO says it won't request passwords or card details by email or phone. One smaller follow-up before you tackle that queue: Mozilla's archive replay has rolled further back into twenty thirteen and twenty fourteen. Those seven republished memory-safety batches aren't new patch work.

I'd put the runtime owner straight onto PHP, with someone else checking for activity before the fix. And if LiteLLM's poisoned release ran, don't let a rollback stand in for secret rotation. Have a good Thursday.
