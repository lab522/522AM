# UEFI disclosure race; PHP telemetry sharpens the patch picture

*A sixteen-year-old firmware flaw exposes servers during network boot, with patch code already public ahead of coordinated disclosure. PHP2Shell telemetry shows uneven exploit success, while Tailscale offers a mitigation and PeopleSoft defenders get a new persistence check.*

Good morning, it's 5:22 AM. Wednesday, the twenty-eighth of October, twenty twenty-six.

Someone on your provisioning network could take over a server before its operating system starts. CVE-2026-97631 is a sixteen-year-old buffer overflow in TianoCore EDK II, the reference code behind most server vendors' UEFI firmware. It's rated nine point five, and the disclosure has gone sideways: researchers had arranged to keep it private until January, but AMI published a fix in a public pull request last month. TianoCore issued an advisory last week. What bugs me is the head start that gives exploit writers while customers wait for vendor firmware.

During PXE boot, the driver listens for ICMP errors and copies them into a five-hundred-and-four-byte field. Both its IPv4 and IPv6 handlers get the bounds wrong: a longer message can overwrite adjacent memory with attacker-controlled bytes. A unicast packet can be enough, giving code execution before Secure Boot and TPM-backed attestation can protect the boot. But it's not an internet entry point: the attacker needs local-network control during boot, and addresses have to be guessed for the particular firmware build. One payload won't work across a mixed fleet. Exploitation isn't known.

I'd chase server and motherboard BIOS updates now, and book the reboots. Until they arrive, switch off unnecessary PXE boot and restrict access to machines while they're provisioning. The small mercy: it's a firmware fix, without Secure Boot keys or revocations to untangle. Home and small-office users aren't affected; unsupported server hardware may never get a fix.

From a disclosure ahead of schedule to a patch deadline nearly upon us: tomorrow's PHP2Shell deadline now comes with a more useful picture of exploit reliability. Wiz saw memory exhaustion succeed in every captured attempt, but the heap leak failed every time. Consecutive requests have to reach the same Apache child process. That's a real constraint, not clearance: Wiz explicitly says its results don't contradict the successful exploitation we covered yesterday.

Delft's lab has counted over fifty thousand exploitation requests from more than six hundred addresses, and AWS saw attempts on the seventeenth, four days before disclosure. CISA also clarifies that KEV can cover attempted exploitation. Meanwhile, Wiz says fewer than fifty-three per cent of initially affected organisations remain vulnerable; Infrawatch's separate host count is now about twenty per cent patched, up roughly thirty-one thousand in a day. Zyxel says no products it currently sells are affected. I'd keep the patch booking, not trade it for an argument about honeypots.

And successful exploitation doesn't always leave the artefact you're hunting: ZDI says the single PeopleSoft CVE actually covers three bugs, with request forgery passing a client check through its default localhost entry. If compromise preceded patching, check docroot slash envmetadata slash data slash environment for unexpected XML files: deserialisation on restart provides another route to code execution, without a JSP web shell. Moving from persistence to prevention, Tailscale now calls Tailworm serious and says most fixes are in public code, but Tuesday's update still had no numbered release despite a promised end-of-day client. Until that client lands, set TS_SSH_DISABLE_FORWARDING=1 in the tailscaled service environment and restart it; forwarding stops, but Tailscale SSH stays available.

The cost of losing that control was painfully concrete in New Mexico: Monday's cyber incident diverted ambulances from the state's only Level I trauma centre for about two hours, though hospitals and clinics resumed on Tuesday. The new BYOD gang's claim of thirty-six thousand compromised machines is unverified and conflicts with UNM's statement that core systems weren't penetrated; staff received phone alerts to unplug desktops, a shutdown communication drill worth rehearsing. At the opposite end of the urgency scale, Mozilla's archive replay has now reached backwards into twenty twelve, with eleven more old memory-safety batches. Widen archive suppression beyond twenty thirteen, or yesterday's filter will miss today's noise.

I'd get a firmware availability answer from the server vendors before the morning disappears. And check that the Tailscale mitigation survives a service restart while you wait for the release. Hope your Wednesday gives you room to get ahead.
