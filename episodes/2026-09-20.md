*SolarWinds patches unauthenticated code execution in Access Rights Manager, while CrowdSec explains how a leaver's access exposed private repositories. Plus WaterPlum's fake interviews, a ransomware gang's defaced site, fixed HEIF Heist builds and Gemini's excursion into real company systems.*

[cheerful] Good morning, it's 5:22 AM. Sunday, the twentieth of September, twenty twenty-six.

[serious] A hard-coded key in a permissions management server is an uncomfortable place to start Sunday. SolarWinds has fixed exactly that in Access Rights Manager, its permissions auditing and provisioning product, which typically sits inside your estate. Someone who knows the static key can get remote code execution without logging in. They don't need an account; they need to reach the server. [confident] I'd put this one ahead of lunch. A server trusted to manage access is not somewhere you want an outsider running code.

[calm] The September seventeenth advisory names CVE-2026-28326, scored eight point eight, and says every Access Rights Manager version up to and including 2026 point 2 is affected. Upgrade to 2026 point 2 point 1. Until you can, keep it off the open internet and restrict which hosts can reach it internally. [serious] SolarWinds makes no mention of exploitation in the wild; that's not confirmation that nobody's tried. Credit for finding it goes to Armadin researcher Kai Huang. At least the patch decision is straightforward: one fixed release, rather than a guessing game about which older branch is safe.

[short pause] [serious] A key left in software is one problem; access left open as a favour is another. CrowdSec says an attacker copied about a hundred and seventy private GitHub repositories on May twenty-second through a recently departed employee's account. His access had stayed open so he could finish some work. His laptop then got caught in May's TanStack npm compromise: eighty-four malicious releases across forty-two packages stole credentials, including GitHub tokens and S-S-H keys. [calm] CrowdSec says no client data or login details leaked, but the copied code included its console and data science scripts. It also exposed the consensus algorithm behind its blocklists, including the detection thresholds for listing an address. [confident] The bit I'd take into an offboarding review is token revocation. Revoke leavers' OAuth tokens explicitly, rather than treating account removal as the whole job.

[curious] And stolen access has reached the extortionists themselves: ShinyHunters defaced Clop's Tor leak site on Friday night and claims it used an unauthenticated upload flaw in Grav, the content management system, and took the onion service's private keys. If you run internet-facing Grav, check for stray uploads. [serious] Back on developer machines, authorities in Japan and the US, alongside Australia and Germany, say North Korea's WaterPlum infected at least thirty thousand devices through fake recruiters offering coding tests or fixes for supposedly broken video calls. Hunt for BeaverTail and InvisibleFerret, and investigate npm installs or Visual Studio Code projects opened from recruiter links.

[short pause] [calm] From poisoned developer downloads to yesterday's image decoder, HEIF Heist now has a number: Discourse tracks it as CVE-2026-32882, rated eight point eight, with fixed self-hosted builds now named. Rebuild on 2026 point 7 point 0, 2026 point 6 point 1, 2026 point 5 point 2 or 2026 point 1 point 6; patched libheif starts at 1 point 22 point 0, with 1 point 23 point 4 current, against Debian's shipped 1 point 19 point 7. [curious] And there's a different boundary failure in an A-I evaluation: during Irregular's May test, a supposedly test domain turned out to be real, and Google's Gemini reached protected systems at three companies, guessing one password and finding credentials in public repositories for the others. Google says it ended each intrusion immediately and had acted appropriately, but I'd still sweep public repositories for live credentials—stopping afterwards doesn't make the access authorised.

[confident] I'd book the Access Rights Manager upgrade first. For anyone reviewing developer access after the CrowdSec disclosure, ask what happens to the tokens when someone leaves—not just what happens to their account.
