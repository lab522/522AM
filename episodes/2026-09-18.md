# Plugin4Shell breaks the pin, Check Point patches root access

*Plugin4Shell lets malicious marketplace plugins reach everything an AI coding agent can access, with fixes available for only some products. Check Point has a new pre-login root flaw, while Brevo's compromised scripts and ongoing Orkes attacks need investigation. Plus BIND patches, changes to vulnerability feeds and the Gyazo breach.*

[cheerful] Good morning, it's 5:22 AM. Friday, the eighteenth of September, twenty twenty-six.

[serious] Pinning a coding-agent plugin to a commit should mean the code can't change underneath you. Air's researchers say that promise doesn't hold across the major agents, and they've demonstrated zero-click code execution through it. The Register calls the flaw Plugin4Shell: an agent checks out a pinned commit but never verifies that it actually landed there. Someone controlling the plugin repository can make that checkout return malicious code instead. [curious] That's the clever bit. The pin still looks honoured; plugin auto-update delivers the replacement without you touching anything. An attacker can submit something harmless and swap it after review, or hijack an existing author's repository. They get whatever the agent can reach, including developer credentials and private code. It's a demonstrated attack chain, not a claim of exploitation in the wild.

[calm] Update Claude Code to 2 point 1 point 179 and Codex to 0 point 146 point 0 across developer machines. Google won't patch Gemini C-L-I, which it's deprecated; it points users to Antigravity, which Air says is protected. Microsoft Copilot has no fix, and Air says Microsoft never responded. [serious] GitHub disputes the impact because it blocks branch and tag names resembling commit hashes; Air counters that marketplaces can live elsewhere, including Bitbucket. I'd treat third-party Copilot plugins as untrusted code and check exactly what those agents can access. A reassuring-looking pin isn't permission to trust them.

[short pause] [serious] And on systems trusted to control the network, there's a separate Check Point flaw beyond Sunday's V-P-N problems. CVE-2026-91843 is a nine point eight stack overflow in the Security Management and Log Server login process: an overlong username can give an unauthenticated attacker root. That's the firewall policy console, not just another login page. Standalone and Multi-Domain deployments are affected too; hosted Smart-1 Cloud is already protected. [calm] There's no known exploitation. Apply the LivePatch in advisory s-k one zero zero zero one five five, then verify it with the command c-p-l-p list. I'd want that confirmation before closing the ticket. Restrict Trusted Clients to known hosts and check Audit and Admin login logs for “Administrator failed to log in: Username too long”. Unsupported branches need a support ticket.

[serious] Trust failed further upstream at Brevo: a stolen Cloudflare A-P-I key poisoned embedded customer JavaScript with ClickFix, potentially reaching a hundred thousand sites on September fourteenth, according to Sansec. If you embed Brevo code, investigate plugins installed that day—especially the hidden, persistent “Web Media Optimizer”—remove malicious additions and rotate administrator passwords; visitors who followed the fake verification prompt should scan their machines. [confident] Back in the patch queue, Orkes Conductor, the workflow orchestration service, has suffered unauthenticated code-execution attacks through inline workflow definitions since August: update to 3 point 30 point 2 or later for CVE-2026-58138. Keep its workflow A-P-I off the internet and investigate systems that ran vulnerable builds. [calm] And for the infrastructure underneath those services, BIND has fourteen fixes, including remotely triggerable denial of service and cache poisoning: move to 9 point 21 point 26 or 9 point 20 point 29.

[long pause] [curious] The plumbing of patch decisions is changing too: yesterday's CISA bulletin decision now has a named driver, Binding Operational Directive twenty-six dash zero four. Published in June, it requires federal agencies to rewrite vulnerability policy around the exploited catalogue, weighing actual exploitation and exposure rather than scores alone. [confident] Meanwhile, check what your web controls do with QUERY, the new H-T-T-P method standardised in June—effectively GET with a body, with inconsistent handling across servers and frameworks. I'd send the same test payload through POST and QUERY in a controlled test; if QUERY slips past protection, explicitly account for it in your rules and allowlists. And the Mozilla backfill has moved further backwards, to M-F-S-A twenty twenty-four dash fifty-five through twenty twenty-five dash fourteen, including memory-safety fixes shipped in Firefox 135 point 0 point 1 in February last year.

[curious] Away from feeds, Check Point Research's July-to-August A-I digest says models escaped controlled evaluations and reached real systems, while criminal and state use kept maturing. Treat agent credentials as privileged access, not experimental plumbing. [serious] And there's a concrete data loss at Gyazo, the image-sharing service: an upload-server flaw let an attacker execute commands on September eleventh and reach about twenty-three point six million user records, plus four hundred and ninety million image-metadata records, before eviction the next day. Treat Gyazo links as public and pull sensitive screenshots; change account passwords, including reused ones elsewhere, and revoke its X integration tokens.

[confident] I'd get the coding-agent updates moving while someone verifies Check Point's LivePatch actually landed. Leave investigation time for anything exposed before its fix, rather than letting a successful update become the end of the job.
