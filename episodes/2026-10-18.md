# One backup secret opens Microsoft 365 tenants

*Attackers used ConnectWise Cloud Backup's application credential to sign in to 173 Microsoft 365 tenants. MALFEX has a new npm loader, Drupal needs urgent updates, and a US breach settlement holds an IT supplier liable alongside its customer.*

Good morning, it's 5:22 AM. Sunday, the eighteenth of October, twenty twenty-six.

The backup application signed in, and Microsoft 365 let it. Attackers have ConnectWise Cloud Backup's own credential, and Huntress has confirmed unauthorised sign-ins across a hundred and seventy-three partner and customer tenants. Every tenant that consented to the application is potentially exposed. Formerly SkyKick, the service backs up cloud mail and files for managed service providers. That means broad permissions already granted, now inherited by whoever holds the secret. No user login took place, so MFA had nothing to challenge.

Microsoft calls this an active supply-chain attack. Activity began on Thursday, with a script moving through tenants in sorted identifier order, seconds apart. Huntress saw ConnectWise service principals assign themselves directory roles in nearly fifty tenants. In one, the attacker reached Global Administrator and added secrets to other applications in about five minutes. That's the bit I'd worry about: access planted elsewhere won't disappear just because the original door closes.

ConnectWise shut customer access to Cloud Backup yesterday, with no restoration time, and says it has no indicators that partner backup data was compromised. That's not an all-clear for Microsoft 365. Disable the implicated applications until ConnectWise confirms all credentials have been reset; older tenants may call them SkyKick Cloud Manager. Check Entra's service-principal sign-in logs, especially for one forty-four dot one seventy-two dot sixty-four dot one twenty-eight. Audit application secrets and certificates added since the thirteenth, removing unauthorised additions, and check for directory-role changes by ConnectWise or SkyKick apps. Enable Microsoft Graph activity logs and review OAuth grants. Revoking user sessions won't end application access, and disabling the app only stops new tokens: existing ones can last another ninety minutes.

And while that trusted application is being disabled, another keeps returning under fresh packaging. The MALFEX npm campaign we covered earlier this month now has imgdecode, with nine hundred and seventy-nine downloads and version 1 point 0 point 3 still live. SafeDep found a nine-line JavaScript wrapper loading a compiled Windows addon. Require the package from a Windows console and it fetches banner dot jpg from GitHub, decrypts it, then injects shellcode into dllhost dot exe. A very small source review can miss a very large problem.

The operator has been replacing removed packages within hours; imgdecode now stands alone, without its earlier imgbundle dependency. If a Windows developer or build host installed it or the earlier MALFEX chain, treat that host as potentially compromised. Isolate it and check persistence, including the MicrosoftEdgeUpdateService scheduled task and a Registry Run key. Rotate exposed credentials; if wallet seed phrases were stored there, move the funds to new wallets.

From malicious dependencies to legitimate modules that open an attack path: Drupal has fixed two critical remote-code-execution flaws, and its security team warns exploits could appear within hours or days. Neither is reachable through core alone, but contributed modules or custom code can expose them, including paths needing no authentication. One affects core's Field UI; the other affects Entity List, a contributed module for building entity lists without Views. Exploitation isn't known yet. I'd use that head start, rather than spend Sunday proving every module combination safe.

For core, the Drupal ten fix is 10 point 6 point 19. On eleven, use 11 point 3 point 19 or 11 point 4 point 10, and update Entity List to 3 point 0 point 10. Drupal twelve pre-releases before beta two are affected too; older unsupported branches get no fix. If you can't upgrade, Drupal calls uninstalling Field UI an effective mitigation. Don't assume Drupal Steward covers every possible attack.

On the WordPress side, seven flaws span six plugins, led by nine point eight PHP object injection in LearnPress through 4 point 4 point 10, where checkout-email input eventually reaches unserialisation. No fixed releases are named: check vendors for confirmed fixes, otherwise deactivate and remove affected plugins, including WP Booking System through 2 point 1 point 0 point 3, whose booking notification emails are readable without authentication.

And responsibility for somebody else's software has a financial edge today: New York and Connecticut secured two point seven million dollars from Boston Children's Health Physicians and its IT provider, XTIUM, over a twenty twenty-four breach, holding both liable. The settlement requires a corrective action plan; if you supply IT services, read that alongside the data-security obligations in your client contracts.

I'd put the ConnectWise tenant checks ahead of the routine Sunday queue. Keep the incident open until you've checked what access the attacker left behind, not just what you've disabled. Have a good Sunday.
