# NGINX needs a patch, not just a reload

*NGINX gets emergency fixes for five unauthenticated code-execution flaws, while Microsoft's official Agent Framework package ships a credential stealer. There's also an afternoon PHP patch window, fresh Java4Shell product guidance and action on actively exploited vulnerabilities.*

Good morning, it's 5:22 AM. Thursday, the nineteenth of November, twenty twenty-six.

NGINX needs an emergency patch, and a reload won't finish the job. F5 has fixed five unauthenticated code-execution flaws in the web server and reverse proxy. The worst, CVE-2026-123007, needs only HTTP/2 enabled on a listening port. It's been there since September twenty fifteen.

The clever bit is broken bookkeeping: cancelling queued responses returns too much flow-control credit. An unsigned subtraction wraps, and that enormous counter becomes a negative response length, sending memcpy outside its buffer. Attackers get code running as the NGINX worker; Xint chained it with a separate Linux kernel SCTP flaw to reach root. There's public demonstration code, limited to a freshly started local Docker container, but no reported evidence of attacks in the wild. I'd move before that changes.

Open-source releases from 1 point 9 point 5 through 1 point 31 point 8 are affected with HTTP/2 on. Upgrade to 1 point 31 point 9 mainline or 1 point 30 point 7 stable; for NGINX Plus, the fixes are 37 point 3 point 0 point 1 or 37 point 0 point 8 point 1. Fully restart, or use the live binary upgrade: a reload leaves old workers running. Can't patch? Set http2 off and remove http2 from listen directives. That blocks two flaws, not all five.

From the code serving your site to the code building it: Microsoft's official agent-framework package on PyPI, its toolkit for building AI-agent workflows, shipped credential stealers in versions 1 point 26 point 1 and 1 point 26 point 2 on Tuesday evening. Both are quarantined; 1 point 26 point 0 remains clean. The second upload arrived after the first was pulled. That's the uncomfortable part: publishing access hadn't been stopped.

The wheels plant a dot-pth file that executes on Python startup, including pip, without importing Agent Framework. It steals stored credentials and requests fresh cloud tokens, while legitimate dependencies keep applications working. I'd treat affected CI runners as a credential incident, not a bad dependency to uninstall. Hunt those versions in build environments and images; isolate affected systems, rebuild clean with 1 point 26 point 0 pinned, and rotate exposed credentials from a clean machine. Review Azure sign-ins and GitHub Actions trust.

Back at the web front door, F5 also has six separate BIG-IP data-plane overflows: unauthenticated traffic can crash the traffic-handling process and may execute code, though none are reported exploited. Check virtual-server configurations against the advisory's affected iRule commands and APM agent pair, then request engineering hotfixes; there's no workaround. And PHP has another release coming, separate from the earlier exploitation chain: all supported branches get security fixes between two and half past two this afternoon, UTC, with the critical issues requiring unusual or non-default setups. Until you upgrade, set session.upload_progress.enabled to zero and restart PHP workers.

Under those applications, yesterday's Java4Shell emergency now has product names attached: Cisco names Catalyst Center and Intersight Virtual Appliance among affected products, without dated fixes or workarounds, while Fortinet has dozens under investigation but clears FortiOS and FortiWeb. Keycloak confirms affected runtime builds in image tags 26 point 8 point 2 dash 1 and dash 2; follow the appliance vendors' advisories rather than assuming a runtime fix is an appliance fix.

And there's confirmed exploitation elsewhere in Java: Apache Roller, the blogging platform, has an unauthenticated deserialisation flaw, CVE-2026-129448, fixed in 6 point 1 point 6. Upgrade, or set enabledForExtensions to false in WEB-INF/web.xml and restart Roller; switching XML-RPC off in the admin screen isn't enough. Staying with active attacks, CISA's KEV now includes code execution in LiteLLM, the AI-model gateway, and unauthenticated code injection in REDCap, the research-data platform: patch LiteLLM beyond the April eighth twenty twenty-six build and follow your institution's REDCap advisory, with federal deadlines of December second and November twenty-first respectively. Synology DSM and BeeStation OS also join the catalogue alongside the previously covered Apache Axis flaw, all due November twenty-first for federal agencies; move the storage appliances to their fixed vendor builds.

From servers to the browser reaching them: Chrome 158 fixes two hundred and four vulnerabilities, six critical, with no exploitation mentioned by Google. Push 158 point 0 point 8127 point 36 and get browsers relaunched—the new build doesn't apply until then.

I'd give exposed NGINX deployments the first change window, with exploited systems taking precedence wherever they're found. Keep an eye on distribution packages too: Ubuntu and Debian hadn't shipped NGINX fixes as of Wednesday. Hope Thursday leaves you a little breathing room.
