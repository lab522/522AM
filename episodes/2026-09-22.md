[cheerful] Good morning, it's 5:22 AM. Tuesday, the twenty-second of September, twenty twenty-six.

[short pause] [serious] Windows trusted the signature. The driver then started killing the security software. A fake LastPass Authenticator page on GitHub, pushed high into search results, has been serving an installer that disables a hundred and forty-five antivirus and endpoint security processes before running the Rapuncel stealer. LastPass itself wasn't breached; its name was the bait, alongside at least forty other brands impersonated by the campaign.

[curious] The download puts a renamed copy of Microsoft's debugger beside a malicious D-L-L, which the debugger loads. That loader gets SYSTEM privileges and installs a Microsoft-attested kernel driver under the guise of an NVIDIA component. Underneath, it's CnCrypt's CcProtect driver, already catalogued by LOLDrivers. Renaming it dropped detections from seven engines to zero. [serious] Delphos found neither file on Microsoft's hash-based blocklist, and at the September seventeenth disclosure, the driver still wasn't blocked. Microsoft said its behaviour didn't meet its definition of a vulnerability because it wasn't a Microsoft component. [confident] That distinction doesn't help the person whose protection has just been switched off. A trusted signature isn't a clean bill of health.

[calm] Hunt for the NvFsFilter service and nvfsflt64 dot sys under Windows, System32, drivers; signing details naming Henan Dafeng Software or CnCrypt are another lead. Watch for driver loads followed by security processes dying. The malware keeps killing protection that restarts, and reruns the stealer, which takes saved browser passwords and wallet files, as well as account sessions. [serious] If that installer ran, I'd treat the machine as a kernel-level compromise: rebuild it, then change every saved password from a clean device. The genuine app comes from lastpass dot com or the official app stores.

[short pause] [curious] Borrowing a trusted name also runs through the new evidence on BlueMoon, the Chrome and Windows exploit kit we covered on the tenth. Volexity's now identified a third Chinese actor in its investigation, U-T-A-zero-five-six-five, using the chain on September third and fourth, before its initial reporting. The lures led to lookalike sites serving real content from the organisations they impersonated, with a hidden iframe delivering the exploit. [serious] The changed payload step downloads chrome_cleanup dot e-x-e inside the running process, strips Mark of the Web and launches it through C-O-M, rather than the earlier command-shell route. It drops a newly documented backdoor, CLEANGULP, giving the attacker a shell and file access. I'd hunt for that foothold rather than call this closed after a browser update: MicrosoftIME dot e-x-e under the user's Local AppData, Microsoft, I-M-E directory, and a scheduled task named MicrosoftIME. Use Volexity's new domain indicators to check proxy logs back to September second.

[long pause] [serious] For something being exploited now, CISA has added CVE-2026-7273 in Zyxel GS1900 switches: an unauthenticated attacker on the local network can turn a crafted web request into operating-system commands through a stack overflow. If you run the GS1900-48HPv2, update beyond firmware 2 point 90, A-B-T-Q point 1, C zero, and move management off user V-LANs; I'd borrow the federal deadline of Thursday, September twenty-fourth.
