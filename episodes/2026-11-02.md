# Hijacked monitoring script drains Polymarket; LXD trusts the wrong certificate

*A hijacked DebugBear script used signed-in Polymarket sessions to steal funds. Canonical has fixes for a client-impersonation flaw in LXD and MicroCloud, while Alpine's post-mortem adds a warning about checking what actually got patched. Also, Binance attribution, NetamLoader hunting clues and exposed WAVLINK routers.*

Good morning, it's 5:22 AM. Monday, the second of November, twenty twenty-six.

A page-speed monitor became a way to empty traders' accounts. On Thursday, malicious JavaScript replaced the DebugBear monitoring script loaded by prediction market Polymarket, and roughly two point six four million dollars reached the attackers in under an hour. DebugBear says its DNS records were compromised through its domain registrar; its early findings point to one customer's website being targeted.

The clever, unpleasant bit is that the code didn't send passwords or private keys anywhere. Hudson Rock's examination found it reused the access traders already had in an open page, finding the site's order-placement code and transaction signer. Wallet logins had positions transferred straight out; email logins had positions sold at progressively worse prices. Polymarket is refunding about two point seven million dollars to seven hundred and twenty-six affected wallets.

DebugBear has told real user monitoring customers to remove its embed code. I'd get unnecessary outside JavaScript off trading and signing pages too: a trusted hostname doesn't make the next file it serves trustworthy. Where you can pin a file, use Subresource Integrity so the browser rejects changed contents. And check what page scripts can ask the signer to approve. Nothing had to steal the key when the page could already use it.

That distinction between having a credential and proving you own it also matters in Canonical's LXD, the Linux container and virtual machine manager, and MicroCloud, which clusters those hosts. CVE-2026-112816 scores ten point zero: an attacker who can reach the HTTPS API can impersonate a trusted client using only its public certificate, potentially reaching root on the host through a privileged account.

The server checked every certificate in the submitted chain against its trust store, although TLS only proves possession of the private key for the first certificate. Attach somebody else's trusted certificate behind your own, and you could become them. That's a nasty little trust mistake. There's no known exploitation.

Refresh the LXD and MicroCloud snaps, then check what actually installed: fixes were still moving into stable channels. Fixed LXD releases are 6 point 10 point 1 and 5 point 21 point 9; older branches need 5 point 0 point 11 or 4 point 0 point 15. MicroCloud needs 3 point 4 point 1 or 2 point 1 point 5, and the community fork Incus needs 7 point 6 point 0. Until patched, restrict API access; there's no configuration fix. Standalone LXD listening only on its local socket isn't exposed through this network route.

Back to stolen funds, the Binance attribution is now official: US investigators name North Korea's TraderTraitor, and virtual-asset operators should block transactions linked to the FBI's six hundred and twenty-eight published laundering addresses. The Hacker News now puts losses at six point four three billion dollars across eleven blockchains; Binance resumed initial withdrawals yesterday and says approximately ninety-five per cent is covered.

Away from exchanges, Kaspersky found the previously undocumented NetamLoader in a CAB archive inside the Windows update download folder of a government-only Windows ten build in Asia, with one known victim and no attribution. Hunt unexpected CABs and configuration files under Windows SoftwareDistribution Download, and watch PatchMyPC-ScriptRunner dot exe loading an AppDomainManager configuration; on the supply-chain side, Alpine now says four GitLab crash attempts partly succeeded and attackers downloaded its container image. Its first upgrade installed 19 point 3 point 4 rather than fixed 19 point 3 point 5, though no repository or release tampering was found through October twenty-seventh and signing keys weren't on that server: check the Ruby inside custom GitLab images, and review registry pulls.

And where Alpine could name the missed fix, WAVLINK still has none named for six ten-point-zero flaws affecting WL-WN530BE1-A firmware V251117 and WN536AX6-A V260507, including 2 point 0 point 0. Public exploits cover unauthenticated remote command injection and a stack overflow, so keep web management off the internet and restrict LAN access as well.

I'd put reachable LXD APIs ahead of routine maintenance, and verify the installed build before closing the ticket. Keep watching for fixed WAVLINK firmware rather than treating restricted access as the finished job. Hope Monday treats you kindly.
