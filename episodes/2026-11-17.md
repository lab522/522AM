# Optimizely tags turn trusted sites into malware delivery

2026-11-17 · [listen](https://raw.githubusercontent.com/lab522/522AM/main/episodes/2026-11-17.mp3)

Brought to you by [Lab522](https://www.lab522.co.uk)

*An Optimizely signup flaw put malicious JavaScript on major websites, stealing payment data and delivering iOS exploits. There's also a remote Linux crash bug, fresh exploitation of management tools, and evidence that autonomous attacks are shortening patch windows.*

Good morning, it's 5:22 AM. Tuesday, the seventeenth of November, twenty twenty-six.

A signup flaw at Optimizely turned other people's websites into malware delivery yesterday. Its Experimentation platform supplies the JavaScript tag sites use to test page changes. That code runs with the same access as the site's own. Attackers used the account signup flow to inject malicious JavaScript into customer projects; Scott Helme's team found a hundred and eighty-eight infected files across a hundred and seventy-eight organisations.

The script loaded, or tried to, on sites including BBC and CNN, with Salesforce and Zoom also affected. It fetched another script from 1688360 dot cc, sometimes hiding the address in Base64. One variant carried its own copy if that fetch failed. Blocking the download wasn't necessarily enough.

The payload swapped cryptocurrency addresses and skimmed card details. It also stole browser data and delivered the Coruna and DarkSword iOS exploit kits. Associated wallets had received roughly seven thousand dollars by yesterday. Optimizely says it's fixed the signup path and removed injected code, though one infected file remained at nine fifty-two last night, UTC. I'd inspect your own Optimizely files rather than assume cleanup reached you. Block that domain; tell affected visitors to review yesterday's crypto transfers and card statements, and update iPhones and iPads. Watch status dot optimizely dot com.

From code arriving through a trusted tag to packets arriving at an ordinary listening port: there's a different Linux kernel problem from Friday's post-break-in flaw. NoisyTCP, CVE-2026-99288, needs no login and crashes the whole machine. It's eleven years old. Crafted TCP traffic races SYN-cookie handling against socket setup, reaching recycled memory before it's ready when receive processing spans queues or CPUs. Kim's lab tests crashed default web and SSH services on QEMU/KVM guests in five seconds to two minutes; that's a demonstration, not evidence of live attacks. A container doesn't spare the host. The upstream fix landed on November third, so check your distribution's kernel update. If you can't patch, disabling SYN cookies or using one receive queue are temporary options, but you sacrifice flood protection or network performance respectively. Separate container network namespaces need their own SYN-cookie change. I'd favour the kernel update over either compromise.

And the management session itself now has a confirmed trap: Huntress says a ScreenConnect technician's workstation ran a guest-pushed batch file, reaching an attacker relay nine seconds later, where Friday's trap had failed. Get host clients and Access agents to 26 point 6 point 5; removing TransferFiles permission is the interim mitigation. The Axis flaw has also moved beyond N-central: Rapid7 saw exploitation against Confluence Data Center with Remote API enabled, so move affected releases through 9.x to 9 point 2 point 28 or unaffected 10.x, or disable Remote API without restarting. N-central's new 2026 point 4 HF3 permanently removes Legacy API access.

Elsewhere in the server queue, UnrealIRCd attacks are now described: they began a day after disclosure and execute commands with server or IRCOp privileges. There's a hot patch or spamfilter workaround if an upgrade must wait; version five and earlier won't get a fix.

The AI gateway queue needs attention too: SANS honeypots saw attempts to chain LiteLLM's MCP test endpoint with Starlette BadHost for unauthenticated code execution, using bracketed Host headers to evade filters. Patch Starlette past 1 point 0 point 1 and update the LiteLLM build carrying it; filter for valid hostnames, not just yesterday's exploit spelling. Yesterday's ARTEX warning now has a clock attached: initial targeting to privileged access in under three hours, with more than two thousand two hundred and fifty downstream Microsoft tenants reached through ConnectWise Cloud Backup. Amazon also captured agents stealing AI-provider keys to power further searches; exposed keys are fuel, not merely loot.

And Google's separate finding goes further: a suspected Russian-speaking operator used an agent to turn patches into working exploits and steal data without human direction during the intrusion. I'd treat newly disclosed internet-facing flaws as same-day work where possible. That shrinking window is changing disclosure too: Project Zero has removed its thirty-day grace period, publishing details at ninety days whether fixed or not. That becomes sixty days on February second, twenty twenty-seven, then thirty on January third, twenty twenty-eight.

Away from servers, Kaspersky suspects Telegram's new widgets are delivering WebRAT through silently launched PowerShell, giving attackers control and stealing wallet and Telegram data. Avoid widgets pending a fix, and treat PowerShell spawned by Telegram on managed machines as an incident. The same researchers say someone re-registered Retadup's old command domains and revived the USB worm to deliver CoffeeLoader. Hunt for 7z.dll in eight-hex-digit folders under ProgramData or LocalAppData, launched through rundll32.

One last distinction between revived malware and revived paperwork: Mozilla's advisory replay now reaches MFSA 2008-51 through 2009-11. Extend archive-date suppression back to that first entry and check for automatically created incidents, rather than opening fresh patch tickets.

I'd put the website team onto their actual Optimizely files while the server team checks kernel availability. Leave room for emergency changes today rather than committing the whole window. Hope your Tuesday gives you a little breathing space.
