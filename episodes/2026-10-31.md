# Claude Code backdoor; Drupal shops under attack

*A tampered Claude Code extension reached developers through Anthropic's official Cursor marketplace account, leaving persistence that an update won't remove. Drupal shops face active exploitation, while a Linux kernel mitigation arrives and investigators attribute the Binance theft to North Korea.*

Good morning, it's 5:22 AM. Saturday, the thirty-first of October, twenty twenty-six.

The Claude Code extension in Cursor's marketplace came with an SSH backdoor on Thursday, served from Anthropic's official account. Cursor says at most five thousand users were affected. The versions to find are anthropic.claude-code 2 point 1 point 312 and 2 point 1 point 313; Cursor auto-updates extensions by default. That's a trusted coding assistant arriving with the developer's own access to their workstation. Microsoft says the malicious packages never reached its Visual Studio Marketplace or npm.

The injected JavaScript ran when the extension loaded, adding an SSH key labelled svc-telemetry and enabling SSH, then opening a reverse tunnel back to the workstation. It also installed startup persistence and sent host reconnaissance to the operator. Cursor says errors and permission requirements blocked SSH access on most macOS and Windows machines. A lucky break, not a clean bill of health.

Version 2 point 1 point 314 followed, but updating or removing the extension doesn't remove what it wrote elsewhere. I'd treat affected machines as incident-response work, not an extension update: preserve evidence, then inspect authorised-key files and confirm the suspect key against Microsoft's published fingerprint before removing it. Microsoft's cleanup guidance also covers platform-specific startup persistence and tunnel identity files; stop the SSH retry processes too. Where telemetry shows credential access, rotate credentials and revoke sessions from a clean device. What bugs me is the silence: Anthropic told Microsoft its systems weren't compromised, but hasn't publicly notified customers, and nobody's explained how the publishing account was taken over.

And patching without checking what's already happened isn't enough for Drupal shops either. The new urgent fix is in Commerce Core, the contributed module behind checkout and orders, not Drupal core. CVE-2026-118539 leaves certain routes and entity fields insufficiently protected, letting unauthenticated attackers bypass access checks. Drupal says it's being exploited and could financially affect shop owners; more than forty-two thousand sites run the module. Its upgrade instructions name 3 point 3 point 13 for the three-series branch, or 8.x-2 point 41 for earlier versions. Audit orders for inconsistencies afterwards. I'd put that audit alongside the deployment, because a patched checkout doesn't correct an order somebody's already changed.

Beyond poisoned tools, there's AI doing the attacking: CrowdStrike says China's state-backed Vapor Panda used the ARTEX agentic penetration-testing framework against more than two hundred organisations, compromising about a hundred and forty sensitive targets in eleven days, with the campaign still active. Watch for bursts of reconnaissance and exploitation against external services, keeping endpoint and identity telemetry connected. And yesterday's WordPress attacks now have a scale: Wordfence blocked sixty-two thousand nine hundred and sixty-nine in twenty-four hours, with attackers polling predictable staging paths to catch an upgrade. Add a hunt for suspicious PHP requests beneath wp-content/upgrade and unfamiliar administrator accounts to the patch work. The exploited-appliance queue has grown too: CISA added Ivanti Connect Secure's root escalation, CVE-2026-111357, and attacker-controlled file upload, CVE-2026-118527, to KEV. Upgrade to 25 point 1 point 1 point 3 or later; the respective federal deadlines are November second and November thirteenth.

Away from confirmed exploitation, the machine you're helping can turn on you: TeamViewer's CVE-2026-111585 lets a malicious host crash the viewer and potentially execute code on Windows, though no attacks have been reported. Update clients to 15 point 83 or later, and apply the separate Host and Remote Management add-on fixes too; there's no workaround. There's better news for yesterday's Linux kernel gap: CIQ now publishes nftables rules blocking IPv4 TCP packets carrying IP options, and warns that disabling MPTCP alone isn't enough. Use those rules for unpatched hosts while Canonical's fixes remain in progress, and check Go services because Go 1 point 24 onwards enables MPTCP listeners by default on Linux. Finally, from preventing access to limiting what access can spend: TRM puts the Binance theft at about six point three six billion dollars across ten blockchains, mostly moved within twenty minutes, and attributes it to North Korea's TraderTraitor with high confidence; Chainalysis agrees. The Ethereum leg used fifty pre-signed EIP-7702 delegations, so inspect standing production authorisations and require fresh, separate signing for each transfer.

I'd establish whether those Cursor versions landed before spending the morning on routine changes. Keep the cleanup evidence separate from the update record, and leave someone watching for the outstanding kernel fixes. Hope your Saturday stays quiet.
