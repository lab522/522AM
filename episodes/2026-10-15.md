# Cisco's mail scanner becomes an attacker's route to root

*Cisco and Palo Alto Networks are patching actively exploited flaws that hand attackers root on security appliances. There are fresh fixes for AhsayCBS and curl, while a Nextcloud app needs updating or removing: disabling it isn't enough.*

Good morning, it's 5:22 AM. Thursday, the fifteenth of October, twenty twenty-six.

An email attachment can now give its sender root on the Cisco appliance meant to catch malicious attachments. Secure Email Gateway has its second confirmed exploited flaw in a month, CVE-2026-76519, scored nine point eight. Path traversal in Advanced Malware Protection lets an unauthenticated sender write arbitrary files and execute commands on the underlying operating system. The gateway only needs to process the mail.

Physical and virtual gateways are exposed on vulnerable AsyncOS releases when File Reputation is enabled and assigned to a mail policy, with Content Scanner Tools older than 25 point 3 point 0 point 5525. There's a mercifully short route to protection: run contentscannerupdate at the CLI, then use contentscannerstatus to confirm that version or later. No upgrade or restart needed for that scanner update. I'd take that option before waiting for a maintenance window.

The AsyncOS fixes are 15 point 5 point 5-014 and 16 point 5 point 0-780; the 16 point 0 branch must migrate. There are no workarounds, and CISA's federal deadline is Saturday. Search system_logs for “System Security” on every cluster member, then cross-check network logs: root lets attackers hide evidence. Preserve forensics before upgrading a compromised instance, because upgrading destroys logs and forensic data. Compromised virtual appliances need rebuilding on a fixed release with renewed credentials.

That same Saturday deadline now applies to Palo Alto Networks, though here attackers need credentials and access to the management interface. CVE-2026-0322 is code injection giving them root on PAN-OS firewalls, with exploitation already observed. PA-Series and VM-Series are affected, along with Panorama appliances; Cloud NGFW and Prisma Access aren't.

Fixed builds include 12 point 2 point 4 and 12 point 1 point 10-h2. On older branches, use 11 point 2 point 13-h3, 11 point 1 point 16-h3 or 10 point 2 point 18-h12. Unsupported releases need moving to a supported fixed version. There's no workaround; restricting management access to trusted internal addresses reduces exposure, but doesn't fix it. Palo Alto calls exploitation “very limited”. I'd still put an externally reachable management interface straight into the emergency queue.

And yesterday's Ivanti story now has a crowd: Previdian counted one hundred and five exploitation attempts from fifty IP addresses, while Shadowserver sees over five thousand six hundred exposed Connect Secure hosts. CISA now urges immediate patching across the board and has published rebuild-and-rotate instructions for compromised instances, covering passwords as well as certificates and other credentials. The cost of stolen appliance secrets comes through in Unit 42's PEERSTITCH investigation: attackers exploited a central FortiManager, stole configurations and keys for more than five hundred managed firewalls, then returned through VPN access and planted a memory-resident implant. Check for rogue localhost device registrations and suspicious dot-tm archives; rotate credentials and certificates held in affected managed configurations.

From gateways to backup servers, there's finally a fix for the AhsayCBS chain we covered on Saturday: apply 10 point 3 point 4 point 45 for version ten, or 9 point 15 point 2 point 70 for version nine, and reboot; versions seven and eight must first move to 9 point 15 point 0 point 0. Earlier attempted fixes were incomplete, a public proof of concept is now available, and both flaws have a Saturday federal deadline. Meanwhile, attackers have planted web shells through Nextcloud's optional Collabora Online — Built-in CODE Server app: update it to 26 point 4 point 303 or remove it, because disabling it doesn't help. The fix arrived in September but the advisory only yesterday; that delay bothers me, and I'd check for shx-star-dot-php shells under apps slash richdocumentscode.

The client can be the target too: a hostile server receiving an HTTP/2 upload can corrupt memory in curl and libcurl 8 point 12 point 0 through 8 point 22 point 0. Upgrade to 8 point 23 point 0; code-execution demonstration material is public, though no attacks are reported.

On the disruption side, Microsoft and Health-ISAC have seized domains supporting YAM Store and the CoGUI and Iron Man phishing services, behind more than a billion messages since January. Check tenants for an unprovisioned PnP Management Shell service principal, and restrict device-code authentication. Back on exposed servers, Rapid7 has published an unauthenticated SQL injection in Channel Software's WebAlliance eCommerce after the vendor didn't reply; it can expose sensitive data, and there's no fix. Block slash preapproval dot asmx at the reverse proxy or WAF, and check SQL Server logs for WAITFOR DELAY patterns.

I'd get the mail-gateway scanner change moving immediately. If you find compromise, preserve the evidence before the upgrade wipes away your chance to understand it. Have a good Thursday.
