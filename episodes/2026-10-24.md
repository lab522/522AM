# PHP's workaround stays; Aruba's management plane needs patching

*PHP has a third code-execution flaw but no emergency fix, while HPE patches eight maximum-severity ArubaOS vulnerabilities. Monday deadlines arrive for two exploited flaws, and new research tracks ransomware automation and theft of developer credentials.*

Good morning, it's 5:22 AM. Saturday, the twenty-fourth of October, twenty twenty-six.

Keep that PHP workaround switched on. A third code-execution flaw, CVE-2026-115560, now has a reserved identifier and an informational advisory, but the fix is waiting for the next regular release. This one needs a peculiar application sequence: configure session.serialize_handler as php_binary or php_serialize, then switch it to php using ini_set before session_start, with upload progress enabled. The PHP Foundation says it doesn't expect that combination in practical use. Fair enough, but SANS also warns there's apparently a bypass for the current fixes. I'd leave session.upload_progress.enabled set to zero until the next update; if you've already done that, leave it alone.

The exploitation picture has become less alarming, not more: Sophos has retracted its successful-exploitation claim, and attempts to deliver the Potassium Mirai variant failed. There still isn't a publicly confirmed compromise. SANS has returned Infocon to green, and neither original PHP2Shell CVE was in KEV as of Friday morning. That's welcome, but the patching figures aren't: Qualys counted a hundred and ninety-nine thousand instances patched within twelve hours, against forty-four million unpatched on supported branches. Another hundred and ten million were running end-of-life versions. Censys separately puts vulnerable services above thirty-four point four million. Those are different measurements, not numbers to add together.

And there's a more straightforward patch decision on the wireless management plane. HPE has released seventy-two ArubaOS fixes, including eight maximum-severity flaws affecting AOS-8 and AOS-10. These are the operating systems behind Aruba's enterprise wireless infrastructure, where a compromised controller can put a whole campus network within reach. The bugs include authentication bypasses and unauthenticated injection paths that can end in code execution. No user interaction needed. HPE hasn't found public exploit code or evidence of exploitation, but I'd put this ahead of routine weekend maintenance. Apply its updates for affected releases; while arranging that, restrict CLI and web management to a dedicated administrative network with firewall controls. Don't leave the management plane generally reachable.

From network management to application dependencies: Pillow, Python's image library, can execute operating-system commands through an attacker-controlled EPS filename, and version 13 point 0 point 0 fixes that alongside other image-processing flaws. Upgrade bundled copies too, but watch the catch: Pillow 13 drops Python 3 point 10, so those deployments need Python 3 point 11 or newer.

Meanwhile, yesterday's VeloCloud warning now has a deadline: CISA added the Orchestrator flaw to KEV, with US agencies required to fix it by Monday, the twenty-sixth; Arista also says deployments are exposed by default, with no configuration that prevents the exposure. The same Monday deadline now applies to the exploited Nextcloud Collabora Online Built-in CODE Server flaw: update that app to 26 point 4 point 303 or remove it, with CISA identifying proxy.php while CODE isn't running as the trigger.

Those deadlines sit alongside fresh evidence of what stolen edge access becomes: Group-IB and NyxLab link more than seventy thousand exposed credentials and LDAP dumps to the actor k0t, exploiting FortiWeb and PAN-OS flaws. Check those patches, then rotate the local administrator and LDAP bind credentials held on the appliances. And SOCRadar found an exposed server containing ransomware affiliates' AI-agent intrusion records, showing actual use of SimpleHelp and FortiClient flaws, with cPanel/WHM also exploited. Patch those products against the identified flaws; what catches my eye is that one reused password unlocked access across their victim's platforms, so replacing it with another shared password wouldn't solve much.

Back inside the application runtime, Imperva's Node2Shell demonstration achieved code execution through crafted Brotli data on the official Node.js 24 point 22 point 0 Linux arm64 image; version 24 point 22 point 1 rejected it, and no exploitation in the wild has been reported. Update bundled Node binaries as well as installations: inbound WAF rules won't cover malicious Brotli responses your application fetches itself.

And the credentials beside those developer tools are targets too: Check Point has spotted Aokigahara stealing AI-tool authentication files alongside Git and cloud credentials. Treat an infected developer workstation as a credential breach, rotate its secrets from a clean machine, and hunt for unexpected reads of those authentication files.

I'd get the Aruba changes moving while checking that nobody's removed the PHP mitigation. Keep Monday's KEV deadlines in view if they apply to you. Hope you get a quiet Saturday.
