*PHP2Shell now has a demonstrated ASLR bypass, while dozens of UK government services remain unavailable. An exploited VeloCloud flaw needs another upgrade, Railway users need to rotate secrets, and Chrome’s approaching certificate distrust deadline needs attention.*

Good morning, it's 5:22 AM. Friday, the twenty-third of October, twenty twenty-six.

PHP2Shell has cleared another hurdle: VulnCheck says its exploit defeats ASLR on x86-64 under PHP's recommended production configuration. It chained a memory leak into code execution on PHP 8 point 4 point 26 with display_errors switched off. So that comforting production setting isn't a shield. The exploit's restricted to paying intelligence customers; its ARM64 work doesn't yet achieve code execution.

CrowdStrike's testing adds an unpleasantly concrete result: one unauthenticated POST makes an Apache mod_php worker launch a shell and run an attacker-chosen command. Cloudflare's attempt count is into the millions, while Infrawatch puts patching at barely six per cent of visible instances. I'd check the runtime bundled inside someone else's product, not just the PHP estate you knowingly bought.

And we now have government outage numbers: thirty-two UK services unavailable, four partially unavailable, with no confirmed central-government compromise. Keep that distinction: Horizon3 has validated exploitation with preconditions it's still characterising, while Dataminr reports no known compromises. CERT/CC's new advisory, VU number seven six three four eight eight, gives interim settings where patching can't happen yet. After remediation, verify the fixed build is actually serving requests. The NCSC also wants a hunt for backdoors planted before the fix.

That same distinction between repaired and clean matters for VeloCloud Orchestrator, the console controlling SD-WAN networks across multiple sites. Arista says attackers are exploiting CVE-2026-114625, a SQL injection that takes even an Enterprise Read Only login up to superuser operator, with possible impact on the host itself. Read-only to operator. That's quite a promotion. It's the third exploited zero-day since late July, and September's fixes don't cover it. On-premises systems need 5 point 2 point 3 point 18, or 6 point 1 point 3 point 10; the fixed 6 point 4 build is 6 point 4 point 2 point 12. Hosted and Dedicated are patched. Until you upgrade, restrict the web interface to trusted administrative networks and review administrator activity for surprises.

But sometimes the access comes from the platform holding your secrets. Railway, which runs developers' applications and databases, says an intruder may have accessed encrypted environment variables and obtained some decrypted contents. It says only a subset of users is affected, but every user should rotate secrets. That's the instruction I'd follow, rather than waiting for a personal notification. Revoke upstream API keys and replace the credentials stored there, including private registry credentials. Railway invalidated its own API tokens and paused deployments; builds are returning, with queues remaining. Researcher Taylor Monahan says wallets whose private keys were stored there have already been drained. How the variables were decrypted remains undisclosed. Railway suspects attacks targeting AI inference providers; a post-mortem is promised.

Away from stolen credentials, there's a door that doesn't even require one: ZDI has disclosed two remote-code-execution flaws in KSMBD, Linux's in-kernel SMB server, with no mainline fix; one is unauthenticated. Check whether ksmbd is loaded, unload it if unnecessary, or keep SMB away from untrusted networks pending a stable-tree fix. And on certificate trust, eMudhra is quitting the global TLS business altogether; Chrome removes emSign ECC Root CA - G3 on the morning of the twenty-seventh of October, Pacific time. Inventory that chain and reissue under another Chrome-trusted hierarchy before then: most affected certificates came through ACME, which won't automatically replace them outside their renewal window.

Keeping a valid certificate won't keep an HTTP/3 service standing, though: FoxIO has released proof-of-concept code for QPACK denial-of-service flaws that can crash servers from one connection. Fixes include quic-go 0 point 57 point 0 and Cloudflare quiche 0 point 29 point 3, alongside lsquic 4 point 9 point 0 and Wireshark 4 point 6 point 2 or 4 point 4 point 12; Bun, Rust's h3 and aioquic were unpatched at disclosure, so keep Bun's HTTP/3 server unexposed, disable HTTP/3 in mitmproxy and set max_field_section_size in h3. Meanwhile, Oracle's quarterly update brings one thousand two hundred and ninety-five fixes: prioritise internet-facing Fusion Middleware and E-Business Suite, with no exploitation flagged for this batch. Its separate Java alert addresses the eMudhra weak-key incident, and the next monthly security update is November the seventeenth.

And patching reaches below the operating system too: Kaspersky found BlackX, a BlackLotus-like UEFI bootkit, targeting Central Asian diplomatic agencies after attackers had already gained administrator privileges. Apply Microsoft's Baton Drop fixes and Secure Boot revocations: the attackers exploit CVE-2022-21894 to install their own Machine Owner Keys and manipulate Secure Boot.

I'd give the urgent changes named owners before the Friday queue gets crowded. And I'd want evidence that each change reached production, not just a closed ticket. Have a good Friday.
