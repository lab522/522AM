# Ivanti's delayed fix becomes an attacker's route to root

2026-10-14 · [listen](https://raw.githubusercontent.com/lab522/522AM/main/episodes/2026-10-14.mp3)

Brought to you by [Lab522](https://www.lab522.co.uk)

*Attackers chained three Ivanti Connect Secure flaws to take over fully patched VPN appliances. Microsoft's record Patch Tuesday and a Linux vhost escape demand attention, alongside refrigeration attacks and flaws affecting PDF processing and container publishing.*

Good morning, it's 5:22 AM. Wednesday, the fourteenth of October, twenty twenty-six, covering the two days since Monday.

Ivanti found part of a Connect Secure flaw in June, put a fix into July's release, and was still backporting it when attackers got to work. Volexity found a fully patched VPN appliance taken over without a login. Root on the box handling remote access, followed by stolen LDAP credentials and a hunt for LAPS passwords. What bugs me is that gap: a scheduled fix in one branch wasn't protection for customers on another.

The chain is clever. A header tricks the login handler into routing requests to protected scripts; a file-write bug then saves a Perl script disguised as a ZIP, briefly enough for another request to execute it before deletion. Finally, a privileged broker trusts configuration data it shouldn't and runs commands as root. The actor re-exploited the appliance for every command rather than leaving a web shell, and tampered with logs. Ivanti tracks the first two bugs as CVE-2026-104935; they're fixed, but the privilege escalation isn't yet.

Patch Connect Secure urgently to the appropriate fixed release: 22 point 8 R2 point 5 or 25 point 1 point 1 point 2; the other fixed releases are 25 point 1 point 3 point 0 and 25 point 1 point 3 point 1. The 22 point 7 R2 point 14 branch and earlier aren't affected. CISA's federal deadline is Friday, the sixteenth. Don't take a clean Integrity Checker result as clearance: it can miss the in-memory activity. Use network and memory forensics, including hunts for an X-DSCGI-PATH header that doesn't match the requested path.

That Friday deadline follows us into Windows. The change ticket we talked about on Saturday now has Microsoft's biggest monthly release attached: one thousand four hundred and thirteen CVEs. The immediate one is CVE-2026-96951, an exploited Windows Shell command-injection flaw that bypasses Mark of the Web warnings. A victim still has to open the crafted file, delivered by email or instant message. Prioritise that update across affected Windows systems; Server 2012 gets no patch, though 2012 R2 does. Then tackle the five Outlook preview-pane code-execution flaws, each scored nine point eight, and ZDI's fifty-nine wormable bugs. The Outlook ones don't need the recipient to open the message. I'd use that distinction to order deployment, rather than let the enormous total turn everything into equally urgent noise.

And on Linux, the worrying distinction is who can open a vhost device. Vhost handles guest traffic through the kernel; Vghost, CVE-2026-74580, lets a local user with device access become root. Its mapping cache survives changes to a live queue's addresses or size, so new addresses get handled using stale mappings without bounds checks. No lucky timing required. It reaches back to kernel 4 point 11, and working demonstrations are public, though there's no public sign of exploitation. A narrower guest-to-host path needs a virtual IOMMU with iommu_platform enabled and vhost in device-IOTLB mode; it can hijack the host's QEMU process. Install your vendor's fixed kernel and reboot. Until then, restrict access to the vhost-net and vhost-vsock device nodes, but that doesn't stop the guest escape. Ubuntu 24 point 04 and 26 point 04 fixes were still in progress yesterday.

From virtual machines to very physical losses: Sunday's French supermarket attack spoiled food, with CERT-FR naming Danfoss AK-SC and AK-SM controllers alongside Dixell and Copeland xweb systems. Get those controllers off the public internet and restrict remote access through a corporate VPN or APN gateway; patching alone doesn't make public exposure safe. Back in the server queue, a crafted PDF can trigger code execution in Ghostscript through CVE-2026-39919: upgrade to 10 point 08 point 0 or a verified backport, including rebuilt container images. If you can't patch, block PDF uploads and disable PDF rendering in ImageMagick; WordPress operators should check with their host. Alongside that, Adobe has fixed one hundred and forty vulnerabilities across ten products. I'd put Commerce and ColdFusion ahead of the desktop applications because they're server-side.

Rebuilding images also means trusting the registry: Docker Hub fixed a two-year-old flaw where converting an account into an organisation transferred its tokens to the nominated owner without changing their secrets, allowing another user to alter images under that owner's identity. Docker found no evidence of exploitation and deactivated identified transferred tokens except those owners asked to retain; there's nothing to install, but check Personal access tokens for unfamiliar entries and revoke them. While you're separating real work from alerts, Mozilla's advisory backfill has now reached twenty fifteen and twenty sixteen. Those Firefox fixes aren't new: correct your feed's date handling if it treats them that way. And a genuine new boundary problem: AIR research says agents could exploit certificate validation in Vercel Sandbox to send data outside approved networks. Don't treat an approved egress destination as proof data stayed inside; watch for Vercel's fix.

I'd give exposed Connect Secure appliances an emergency change and a separate investigation, not just a patch ticket. For virtualisation hosts, check that the fixed kernel is actually running after the reboot. Have a good Wednesday.
