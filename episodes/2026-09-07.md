# Router takeovers, N-central hotfixes and identity servers without identity checks

Good morning, it's 5:22 AM. Monday, the seventh of September, twenty twenty-six. 522 AM is brought to you by Lab522, a technology partner for mid-market businesses, providing cyber security services and enterprise operational software. Email hello at lab522 dot co dot uk if you think we can help your business. Attackers are taking over MikroTik routers with internet-facing SSH, chaining two recently disclosed RouterOS flaws. One provides an SSH authentication bypass, and a patch arrived late last week. A router that answers to somebody else is a rather bigger problem than a broken login screen.

If you run MikroTik with SSH exposed to the internet, get the patched RouterOS release from MikroTik's advisory and take SSH off the public side while you arrange it. The fixed version hasn't been named here. SANS is advising you to assume compromise, so don't mistake installing an update for proving the router's clean. Review its configuration and access history as well.

From the box carrying your traffic to the box managing your servers: N-able has issued its fourth N-central hotfix in five weeks. N-central is a remote monitoring and management platform, so code execution there puts an attacker on infrastructure trusted to administer other machines. That's the one I'd move straight to the front of the maintenance queue.

Every on-premises N-central build below 2026 point 3 point 1 point 14 needs Hotfix Four, including servers updated to Hotfix Three just a day earlier. The flaw allows unauthenticated remote code execution and carries a score of ten. N-able's incident notice says it's been exploited; its release notes say that remains unconfirmed. That's an awkward contradiction, but not a good reason to wait. Treat it as a live threat and apply Hotfix Four. Yesterday's change ticket doesn't get you out of today's.

Staying with remote management, attackers are also abusing backdoored ScreenConnect instances to transfer and execute payloads on newly connected clients. The campaign uses a four-stage VBScript chain and behaves like a worm: connecting another host can give the malicious setup another place to run. Check the integrity of ScreenConnect clients and instances, and investigate unexpected script execution around new connections. The tool you use to reach a machine shouldn't become the delivery van for its infection.

Separately, ConnectWise has warned of a new ScreenConnect Remote Access vulnerability with no patch yet, and has published temporary mitigations ahead of a fix planned for later this week. If you run it, consult that advisory now. Don't assume the vulnerability and the backdoored-client campaign are the same thing; there's no established link between them in today's coverage.

And remote code execution isn't staying inside the management estate. Attackers are exploiting the StyleSmuggler zero-day to execute code and plant a stealthy backdoor in Adobe Commerce and Magento online stores. No affected versions or fixed release have been named. If you operate either platform, check the vendor's current guidance and investigate unexpected code changes and backdoors on the store. The important distinction here is that exploitation has already happened; waiting for a tidier advisory isn't a detection strategy.

While those attackers are breaking into servers, others are simply ringing the people with access. A widespread theft-and-extortion cluster is targeting executives through fake IT help desk calls, adversary-in-the-middle token theft and access to Microsoft 365 and other SaaS services. The call supplies the trust, and the stolen token supplies the access. If your help desk is being impersonated, investigate the resulting sessions and data access, not just whether somebody typed a password into the wrong page.

There's scale behind the phishing-service side of that problem, too. BigBear 2 point 0 has been used to bypass MFA at two hundred and fifty-eight organisations and steal more than five thousand Microsoft 365 credentials. Separately, JSCeal malware can bypass Google authentication using stolen session cookies. Different routes, same operational catch: a successful MFA event doesn't settle whether the session belongs to the user. Check suspicious session activity and revoke stolen sessions as part of containment, rather than stopping at a password reset.

One more active campaign before the new flaws: North Korean hackers are targeting automotive and media organisations in South Korea with a Linux espionage toolkit that embeds a backdoor in HAProxy, the proxy often sitting directly in the application traffic path. That's a useful hiding place for long-term surveillance. For teams in that target group, HAProxy binary integrity deserves attention alongside configuration review; a normal-looking configuration won't establish that the executable underneath it is clean.

Right, now to identity infrastructure, where two newly disclosed flaws are particularly nasty. The first is in 389 Directory Server, the LDAP engine behind Red Hat Directory Server. CVE-2026-18922 scores nine point eight and is reachable over the network with no credentials and no user interaction. An attacker attempts a SASL PLAIN bind as Directory Manager using the wrong password, then completes a SASL ANONYMOUS bind on the same connection. The old identity survives in a Cyrus SASL property and gets attached to the successful anonymous bind.

So the password fails, the anonymous login succeeds, and the connection inherits Directory Manager authority. That's directory administration without a valid credential, with consequences for applications relying on that directory for identity and access. Red Hat Directory Server eleven and twelve are identified as affected, but exact vulnerable builds and a fixed release haven't been specified. Check Red Hat's advisory against deployed packages and restrict LDAP reachability to the clients that actually need it while you establish remediation.

The second identity flaw reaches a similar destination by a different route. FreeIPA is Red Hat's identity server, handing out Kerberos tickets and managing identities across Linux estates. CVE-2026-76578 also scores nine point eight, with network access, no login and no click. Its self-managed OTP token access rule neither requires authentication nor limits which extra attributes can accompany a token entry. Combined with a separately tracked directory-server access-control flaw, that lets an anonymous LDAP client create an attacker-controlled Kerberos principal and add it to the administrators group. An admin identity conjured out of a token-creation request. Don't assume that separate dependency is the SASL bug we just covered. Exact package ranges and a fixed release aren't specified for FreeIPA either; check the Red Hat guidance for both parts of this chain.

Which brings me to a remote-execution flaw with an actual upgrade destination. Dell Secure Connect Gateway is the support gateway connecting infrastructure to Dell's support services. CVE-2026-61410 is missing authorisation on requests that can execute commands remotely. It scores nine point four, and an attacker needs network access but no login or user interaction. That gives them code execution on a support gateway, not merely access to a diagnostic page. For SCG five, upgrade the appliance to 5 point 36 point 00 point 16 or later, and the application edition to 5 point 36 point 00 point 00 or later. Dell recommends doing that at the earliest opportunity.

For another network-facing application component, there's now a public TantoSec exploit chaining an AES-CBC padding oracle in Telerik UI for ASP.NET AJAX into unauthenticated remote code execution. Telerik supplies interface components embedded in web applications, so this may sit inside software your developers own rather than appear as a standalone service. The catch matters: the exploit works only against a specific non-default configuration, and Progress patched the chain in July. Check both the application's configuration and whether the July fixes reached the deployed component. Public exploit, yes; every Telerik application instantly vulnerable, no.

Back on network equipment, Advantech's WISE-6610 family of industrial LoRaWAN gateways has two public command-injection exploits affecting firmware 1 point 2 point 1, build 20251110. Both score nine point nine and require a low-privilege login over the network, with no user interaction. One hits Basic Station certificate deletion; the other hits the Node-RED library handler. In both cases, the act parameter becomes a route to command execution on the gateway connecting sensor networks to upstream services.

For the Node-RED flaw, CVE-2026-79698, upgrade affected WISE-6610 and WISE-6610P variants to 1 point 2 point 4, build 20260821. Don't assume that also settles the certificate-deletion flaw: a fix for that one hasn't been specified. Restrict management access and check Advantech's guidance for that second issue. A low-privilege account shouldn't be a shell with a modest job title.

Two smaller network-device warnings fit alongside that. D-Link DIR-822A firmware A_101 has a remotely reachable stack buffer overflow in udhcpcd, with no login or click required and a public exploit. Linksys RE7000 firmware 2 point 0 point 15 has a public command-injection exploit in its ping-test handler, reachable remotely with a low-privilege login. Safe firmware versions haven't been identified for either. If you run those builds, check vendor guidance and keep their reachable attack surfaces away from untrusted networks; a public exploit isn't proof of live attacks, but it does shorten the comfortable part of the response window.

And public code is also out for privilege-escalation zero-days involving CrowdStrike, Nvidia and Avast. Nightmare Eclipse's proofs of concept produce a shell with SYSTEM privileges. Product components, affected versions and fixes haven't been identified, so the useful action is to watch those vendors' advisories rather than guess which installed package needs replacing.

Finally, the breaches put some human scale on those footholds. Mathspace, the online maths-learning platform, says attackers stole data concerning more than a million students, staff and parents after breaching its internal Metabase reporting system. Metabase turns connected data into queries and dashboards; it isn't just a place to admire charts. If you run it, review its exposure and the data its connections can reach. The initial breach mechanism hasn't been disclosed, so there's no basis for pinning this on a particular Metabase vulnerability.

And at Trezor, the August breach of shipping and logistics provider ShipMonk now affects eighty-one thousand customers, including another sixty-seven thousand US customers. The breach is at the fulfilment provider, not an established compromise of the hardware wallets. For affected customers, be wary of follow-up messages using genuine order context to sound convincing. A supplier's customer records can give a scammer a very good opening line.

I'd give internet-exposed MikroTik SSH and on-premises N-central the first emergency change slots today. Then I'd check identity-server exposure and remote-management integrity, while keeping a close eye on the ScreenConnect mitigation notice and promised patch. 522 AM, brought to you by Lab522.
