N-able has released its fourth N-central hotfix in five weeks, and even servers updated to hotfix three a day earlier need another update.

If you run on-premises N-central below 2026 point 3 point 1 point 14, install hotfix four. N-central is the remote monitoring and management platform sitting above the machines you administer, so unauthenticated remote code execution there puts the management tier at risk, not just another isolated server. The flaw carries the maximum severity rating, but the exploitation messaging is muddled: N-able's incident notice says it's been exploited, while its release notes call that unconfirmed. I'd treat the incident notice as the decision-maker here; conflicting wording isn't a reason to leave the control room unlocked.

That same management reach is doing the damage in a separate ScreenConnect campaign. Attackers are using backdoored instances and modified clients of ConnectWise's remote-access software to transfer and execute payloads on newly connected systems, delivering a four-stage VBScript chain. It's worm-like activity: the support connection becomes the delivery route. If you operate ScreenConnect, investigate unexpected client modifications and script execution around new connections, rather than looking only for an inbound exploit.

Separately, ConnectWise has warned about a new ScreenConnect Remote Access vulnerability, with a patch planned for later this week. Temporary mitigations are available from ConnectWise now; follow that advisory while waiting for the fix. Don't conflate the two stories: there's no established link here between that new flaw and the backdoored-client campaign.

Moving from the management tier to the network edge, MikroTik routers with internet-exposed SSH are being hijacked through a chain of two recently disclosed RouterOS vulnerabilities. One allows SSH authentication bypass, and a patch arrived late last week. SANS is blunt about exposed devices: assume compromise. If you run one, apply the relevant RouterOS update and investigate the device as a potential attacker foothold; restoring the front-door lock doesn't tell you who already walked through it.

Meanwhile, online shops have their own unwelcome tenant. Attackers are exploiting the StyleSmuggler zero-day to execute code and plant a stealthy backdoor on Adobe Commerce and Magento stores. That gives them execution inside the shop, where the application and its data live, rather than merely a way to deface a page. The affected version range and a fix haven't been named, so operators should watch the vendor's guidance and investigate unexpected application changes and backdoors now.

And attackers don't always need a software flaw to get inside. BigBear two point zero, a phishing-as-a-service framework, has bypassed MFA at two hundred and fifty-eight organisations and stolen more than five thousand Microsoft 365 credentials. The precise bypass mechanism hasn't been described, so don't automatically label it a reverse-proxy attack. For Microsoft 365 investigations, the useful point is narrower: an MFA-success event doesn't, by itself, clear a suspicious sign-in.

That authentication problem has a second route in JSCeal, compiled V8 JavaScript malware with credential theft, surveillance and traffic-interception capabilities. It can bypass Google authentication using stolen session cookies. Here, the attacker isn't solving the login challenge; they're taking an already-open session. If JSCeal is found on an endpoint, include Google session revocation in the response, rather than treating a password reset as the finish line.

One more active intrusion story before the newly disclosed flaws: North Korean hackers are targeting automotive and media organisations in South Korea with a Linux espionage toolkit that embeds a backdoor in HAProxy. HAProxy is the proxy and load balancer often sitting directly in an application's traffic path, which makes it a particularly awkward place to hide long-term surveillance. For organisations in that target group, checking HAProxy's integrity belongs alongside the usual hunt for unfamiliar processes. The familiar process may be the problem.

Now, the new identity flaws are the ones I'd lose sleep over. In 389 Directory Server, the LDAP directory underlying Red Hat Directory Server, an attacker can ask to bind as Directory Manager with the wrong password, then complete an anonymous bind on the same connection. A stale identity left in a Cyrus SASL auxiliary property survives the failed attempt and gets attached to the successful one. Wrong password, anonymous login, directory administrator. That's quite a promotion.

For CVE-2026-18922, the result is Directory Manager authority without valid credentials, giving the attacker administrative control over directory contents and permissions. It's improper authentication, reachable over the network with no login and no click, scoring nine point eight. Red Hat Directory Server eleven and twelve are identified, but precise affected builds and a fixed version haven't been named. If you run either, prioritise the vendor advisory and restrict untrusted access to LDAP while you establish the remediation path.

Staying with Red Hat identity, FreeIPA is the server handing out Kerberos identities and managing Linux access across a domain. CVE-2026-76578 lets an unauthenticated LDAP client abuse the access rule for self-managed OTP tokens, which neither requires authentication nor limits the extra attributes added with a token entry. Combined with a separately tracked directory-server access-control evaluation flaw, that allows an attacker to create a Kerberos principal they control and put it in the administrators group.

Again, it's network-reachable, with no credentials or click, and scores nine point eight: the prize is a new administrator identity inside the system that governs access elsewhere. Red Hat Enterprise Linux seven and ten are identified, without package-level ranges. Check FreeIPA-specific remediation for those deployments, and don't assume the directory-server bug in that chain is the stale-identity flaw we just covered; that connection hasn't been established.

Which brings me back to infrastructure with a clear update target. Dell Secure Connect Gateway is the support gateway between your infrastructure and Dell's support services. CVE-2026-61410 is missing authorisation: a specially crafted request bypasses restrictions and can execute commands remotely on the gateway. It's reachable over the network with no login and no click, scoring nine point four; compromise lands on a system positioned to communicate with supported infrastructure.

If you run the Secure Connect Gateway five point zero appliance, upgrade anything before 5 point 36 point 00 point 16. For the application edition, the fixed threshold is 5 point 36 point 00 point 00. Dell recommends upgrading at the earliest opportunity. Those are different builds for different deployment types, so check which one you're actually maintaining.

While we're on remote execution, there's a public exploit for a Telerik UI for ASP.NET AJAX chain. That's a web-interface component library embedded in ASP.NET applications, and TantoSec's proof of concept turns an AES-CBC padding oracle into unauthenticated code execution. The catch matters: it works only in a specific, non-default application configuration, and Progress patched the chain in July. Check the embedded Telerik component and whether the application's configuration matches the vulnerable setup; a public exploit isn't proof that every Telerik deployment is exposed.

Back at the edge, a new D-Link flaw has a public exploit, though exploitation in the wild hasn't been established here. CVE-2026-86296 affects the DIR-822A release A underscore 101: an unsafe strcpy in udhcpcd's serverpacket code causes a stack-based buffer overflow. It's remotely reachable with no credentials or click and scores ten, making memory corruption on the router available without an authenticated foothold. The concern is loss of control of the router and the network position it occupies; a specific code-execution outcome hasn't been described.

For that D-Link release, check the vendor's remediation guidance and keep untrusted traffic away from the affected service where your deployment allows it. The similarly exposed-sounding Linksys issue has an important difference: it needs a low-privilege login. CVE-2026-86299 affects RE7000 range extenders on firmware 2 point 0 point 15, where the PingTest handler accepts command injection through the target IP, packet size or repetition-count arguments. A diagnostic feature has become a route to operating-system commands.

That Linksys attack runs over the network, needs no click, and scores nine point nine, with a public exploit available. It gives an authenticated attacker command execution on a device extending your network, not merely permission to send a few pings. If you run that firmware, restrict who can reach and authenticate to its management interface while checking Linksys's fix guidance. Don't mistake the near-maximum score for an unauthenticated attack.

The same command-injection pattern turns up in Advantech's WISE-6610 industrial LoRaWAN gateways, which bridge sensor networks to backend services. Two flaws affect firmware 1 point 2 point 1, build 20251110, across the NB, EB, TB, JB and CB variants, their EL counterparts, and the WISE-6610P DEA, DNA and DTA models. Both take the act argument into command injection, both need low-privilege credentials over the network, neither needs a click, and each scores nine point nine. Public exploits exist for both, putting gateway execution within reach of someone with a limited account.

For CVE-2026-79698, the vulnerable path is the Node-RED library handler, and upgrading to 1 point 2 point 4, build 20260821, resolves it. The other, CVE-2026-79697, sits in the Basic Station certificate-deletion handler; don't assume that same build fixes it without confirmation. In practice, these flaws turn limited gateway access into commands on the bridge between field devices and backend systems. Prioritise the confirmed Node-RED update and get a separate remediation answer for the certificate handler.

One more application flaw before the breaches: Next4Biz CSM is customer-service management software, sitting around customer records and support workflows. CVE-2026-7861 affects releases through the vendor's 07092026 marker and allows code injection through deserialisation of untrusted data. It's network-reachable with no credentials or click and scores nine point eight, placing execution inside the customer-service application and threatening the data it can access. The vendor didn't respond to early disclosure contact; if you run it, seek a supported fix and review whether untrusted users need direct access to that deployment.

That application-data boundary is exactly where Mathspace has been hit. The online maths learning platform says attackers stole data affecting more than one million students, staff and parents after breaching its internal Metabase reporting system. Metabase turns connected data into dashboards and queries, so the reporting tier can be a route to a much larger collection than its modest interface suggests. If you operate Metabase, review its external exposure and what its database connections can read; the initial intrusion mechanism here hasn't been disclosed.

And the Trezor breach now reaches eighty-one thousand customers, after the hardware-wallet maker identified another sixty-seven thousand affected US customers in August's breach at shipping and logistics provider ShipMonk. The expansion is in the fulfilment supply chain, not evidence that the hardware wallets themselves were compromised. If you receive Trezor-themed follow-up messages, verify them independently rather than trusting apparent knowledge of a purchase.

I'd put N-central hotfix four and exposed MikroTik routers ahead of speculative score-chasing today, with compromise checks alongside the updates.
