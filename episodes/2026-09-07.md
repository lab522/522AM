Start with MikroTik: attackers are chaining two recently disclosed RouterOS flaws to take over routers with SSH exposed to the internet.

The chain includes an SSH authentication bypass, and MikroTik released a patch late last week. SANS ISC's advice is to assume compromise, so if you operate an exposed RouterOS SSH service, I'd treat this as an incident investigation alongside the update, not a patch-and-forget job. Exact affected and fixed RouterOS versions haven't been specified here. A hijacked router puts an attacker on the box controlling your network's traffic; that's rather more consequential than an unwanted shell on a spare workstation.

From the network's front door to the tool with keys to the machines behind it: N-able has issued its fourth N-central hotfix in five weeks. N-central is its remote monitoring and management platform, often sitting above a whole fleet of customer systems, and the latest flaw allows unauthenticated remote code execution with a maximum severity score of ten. Every on-premises build below 2026 point 3 point 1 point 14 needs Hotfix Four, including servers given Hotfix Three just a day earlier.

There's an awkward contradiction: N-able's incident notice says exploitation has happened, while its release notes call that unconfirmed. I'd take the more urgent account seriously rather than wait for the wording to agree. If you run an affected on-premises N-central server, get Hotfix Four on and investigate possible compromise; control of the management server is a foothold pointed straight at the estate it manages.

Staying with remote management, ScreenConnect has two separate problems today, and they're worth keeping separate. Attackers are using backdoored ScreenConnect instances and modified clients to transfer and execute payloads on newly connected systems. The worm-like activity delivers a four-stage VBScript chain: a fresh support connection becomes the delivery route onto another host.

For ScreenConnect operators, check the integrity of the clients you're distributing and investigate unexpected script transfers or execution when hosts connect. Separately, ConnectWise has warned of a new ScreenConnect Remote Access vulnerability, with temporary mitigations available and a patch planned for later this week. Apply ConnectWise's mitigation instructions for that flaw; don't assume the promised patch explains or fixes the backdoored-client campaign.

And remote execution is already being put to work on shopfronts. Attackers are exploiting the StyleSmuggler zero-day to execute code and install a stealthy backdoor on Adobe Commerce and Magento stores. That's control inside the store application, not merely a defaced landing page. If you operate either platform, investigate unexpected code and backdoors now; affected versions and a fix haven't been specified.

Right, from confirmed attacks to new flaws with thoroughly unpleasant reach. CVE-2026-18922 affects 389 Directory Server, the LDAP directory underneath Red Hat Directory Server, with Red Hat Directory Server 11 and 12 implicated. It's an authentication failure that grants Directory Manager authority over the network with no credentials and no click, scoring nine point eight.

Here's the trick: an attacker attempts a SASL PLAIN bind as cn=Directory Manager with the wrong password. The failed attempt leaves that identity in a Cyrus SASL auxiliary property; a subsequent successful anonymous bind on the same connection can inherit it. Wrong password, then anonymous login, then directory-wide authority. The blast radius is the directory's identities and access data, which is why I'd put this well ahead of a flashy score on an obscure appliance.

Which brings me to FreeIPA, Red Hat's identity server for Linux estates, handing out Kerberos tickets and managing users and access. CVE-2026-76578 is another nine point eight, reachable over the network with no login and no click. Its self-managed OTP token access rule neither requires authentication nor limits the extra attributes added with a token entry.

Combined with a separately tracked flaw in the directory server's access-rule evaluation, an anonymous LDAP client can create an attacker-controlled Kerberos principal and add it to the administrators group. An admin identity conjured out of a token-creation operation: this one's nasty. Red Hat Enterprise Linux 7 and 10 are implicated, but exact package cut-offs and fixed builds for these identity flaws haven't been specified. If you operate these services, prioritise identifying vulnerable packages and limiting untrusted LDAP reach while remediation is established; don't mistake the separate access-rule flaw for the SASL bug we just covered.

Another high-value foothold sits in vendor support infrastructure. Dell Secure Connect Gateway connects your infrastructure to Dell's support services, and CVE-2026-61410 lets an unauthenticated network attacker send a crafted request that bypasses authorisation and executes commands on the gateway. No click, nine point four, and the target is a system already positioned to interact with the equipment it supports.

For Secure Connect Gateway 5 point 0 Appliance, upgrade anything before 5 point 36 point 00 point 16. For the Application edition, upgrade anything before 5 point 36 point 00 point 00. Dell recommends upgrading at the earliest opportunity; between the reachable command execution and clear fixed versions, that's a very straightforward job to put into today's change queue.

Back to network equipment, but these next ones have public exploits rather than confirmed attacks. CVE-2026-86296 is a stack-based buffer overflow in D-Link DIR-822A firmware A_101, in the udhcpcd serverpacket code's use of strcpy. It's reachable remotely with no login and no click, and scores ten. The stated weakness is memory corruption, not a demonstrated router-takeover outcome; my read is that a public exploit against this network service deserves immediate exposure review, but D-Link haven't identified safe firmware here.

On nearby ground, CVE-2026-86299 affects Linksys RE7000 firmware 2 point 0 point 15, a Wi-Fi range extender. Its PingTest handler accepts arguments for the destination, packet size and count that can produce operating-system command injection. An attacker needs low-level credentials, but can attack over the network without a click; the score is nine point nine, and an exploit is public. That turns a diagnostic feature into command execution on a device inside the network, so restrict access to that interface while a fixed firmware version is established.

The same command-injection theme reaches industrial networks through Advantech's WISE-6610 family, LoRaWAN gateways sitting between wireless sensors and upstream services. Two public exploits affect firmware 1 point 2 point 1, build 20251110, across the listed standard, EL and P variants. Both need low-level credentials, work over the network without a click, and score nine point nine. In each case, an act argument lets an attacker inject commands on the gateway, putting the sensor-network bridge itself under threat.

One route is the Basic Station certificate-deletion handler, tracked as CVE-2026-79697. The other is the Node-RED library handler, CVE-2026-79698, for which an upgrade to 1 point 2 point 4, build 20260821, is explicitly identified as the fix. If you run affected WISE-6610 firmware, take that upgrade for the Node-RED issue, but don't assume it also fixes the certificate-deletion route without confirmation. Shared symptom, separate fix verification.

One more application flaw before the wider news: Next4Biz CSM is customer-service management software, holding the workflows and records your support teams use. CVE-2026-7861 affects releases through version 07092026 and allows code injection through deserialisation of untrusted data. It's nine point eight, over the network with no authentication and no click, putting the application and its customer-service data at risk. The vendor didn't respond to early contact about the disclosure, and no fix is identified, so affected operators need to review untrusted reach to the service rather than wait quietly for a patch.

While we're on application code execution, there's a public TantoSec exploit for Telerik UI for ASP.NET AJAX, the component suite embedded in web applications. It chains an AES-CBC padding oracle into unauthenticated remote code execution, but only in a specific non-default application configuration. Progress patched the chain in July. Check the Telerik components inside your applications against that July fix, and check the configuration requirements before treating every installation as equally exposed; the condition matters more than the headline.

From public exploits to an actual Linux espionage operation: North Korean attackers are deploying a toolkit against automotive and media organisations in South Korea, embedding a backdoor in HAProxy for long-term surveillance. HAProxy is the reverse proxy and load balancer that may already sit in front of your applications, making it a useful place for malicious code to look ordinary. For organisations in that target set, checking the provenance and integrity of deployed HAProxy builds belongs in the investigation. Looking only for a suspicious new service risks missing an existing service that's been altered.

And once attackers have a foothold, another story shows why the session matters as much as the password. JSCeal is compiled V8 JavaScript malware with credential theft, surveillance and traffic-interception capabilities, and it can use stolen Google session cookies to bypass authentication. An already authenticated session is the prize. If you're responding to JSCeal, include session revocation and account-session review, rather than stopping at a password reset.

That brings us to two breaches where the interesting boundary is outside the obvious product. Mathspace, the online maths learning platform, says attackers stole data concerning more than one million students, staff and parents after breaching its internal Metabase reporting system. Metabase is a business-intelligence tool that queries organisational data: an internal dashboard can still be a very large door into personal information. If you run it, review its exposure and the data reachable through its connections; the particular intrusion method hasn't been disclosed.

The other boundary is fulfilment. Trezor says the August breach at shipping and logistics provider ShipMonk affects an additional sixty-seven thousand US customers, bringing the impact to eighty-one thousand customers. That's a provider breach affecting hardware-wallet customers, not evidence that the wallets themselves were compromised. If you use a logistics provider, the concrete check is what customer information you've passed into that provider's systems and how far a breach there would reach.

I'd deal first with internet-exposed MikroTik SSH and affected on-premises N-central servers, combining remediation with compromise checks. Then I'd move the identity-server flaws and Dell gateway updates to the front of the queue, while keeping an eye on ConnectWise's promised patch and the unresolved firmware fixes. 522 AM, brought to you by Lab522.
