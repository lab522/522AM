# Azure APIM attackers leave stolen credentials valid

*Attackers have stolen credentials from Azure API Management Classic, and Microsoft's fix doesn't invalidate them. An abandoned ASP.NET security library is also under active exploitation, while new findings sharpen the response to Expressway attacks and AI-provider breaches.*

Good morning, it's 5:22 AM. Tuesday, the twenty-fourth of November, twenty twenty-six.

Microsoft has fixed an Azure API Management flaw, but credentials stolen through it still work. APIM is Microsoft's hosted API gateway, sitting in front of applications and holding credentials for services behind them. Norway's security authority names Equinor and Skagerak Energi among those affected; both say they've found no evidence of data theft.

Microsoft identified the problem on the eighteenth and deployed its mitigation the next day, rotating Microsoft-controlled keys. It says Classic instances outside its recommended security configurations allowed unauthorised management access, including secrets management. That covers ignored network guidance or secrets stored directly in APIM rather than referenced from Key Vault. Developer and Basic tiers are affected, alongside Standard and Premium. Classic Consumption and all v2 tiers aren't.

If you run affected Classic tiers, treat stored secrets and named values as compromised and rotate them. I'd put forgotten development instances in that search too: a test gateway can still hold a very real credential. Investigate the services those credentials reach and review available logs. Microsoft says remediation is fully deployed; Norway's authority still advises checking runtime patch thresholds. The distinction that matters: fixing APIM doesn't stop a stolen key being used directly against another service.

And there's another urgent job beyond yesterday's rendering patch: an abandoned ASP.NET security library is now an actively exploited route into servers. Mandiant flags CVE-2026-131914 in Idunno.AntiCsrf versions 0 point 9 point 1 point 0 and 0 point 9 point 1 Beta, scored nine point three. Its WebForms module deserialises attacker-controlled CSRF form data without verifying a signature or MAC. One unauthenticated POST can run code as the IIS worker process. A security check becoming the execution path. That's grim. There's no patch: find references to Idunno.AntiCsrf in Web.config and application bin directories, then replace the library with a supported defence. Hunt anomalous POSTs to dot aspx endpoints; if you find exploitation, rotate application configuration secrets and inspect webroots for unauthorised files.

On the other live attacks, Expressway's US agency deadline passed yesterday, while Cisco updated its advisory to say it has no direct evidence of exploitation, despite CISA's listing and F6's observed case. Check erlang.log for F6's indicator, nodeup followed by “wombat at 127 point 0 point 0 point 1”; F6 also says the attack scripts suggest AI assistance. Meanwhile, yesterday's MailAssure flaw is now in KEV, with a Thursday deadline for US agencies, and N-able says it emerged from the Hosted Cloud breach investigation. API and OAuth tokens have been revoked, so integrations need replacement credentials; Local Cloud operators still need to verify their patch status.

Outside that confirmed-exploitation queue, Cribl Stream, which routes telemetry between systems, has critical flaws through 4 point 20 point 4: read-only access can become Leader code execution, while attacker-controlled REST pagination data can execute on a Worker without a Cribl login. An SSO flaw can also steal sessions; check Cribl's advisory for the fixed build, because these records don't name one. From securing those systems to buying the suppliers, CrowdStrike has agreed to acquire Zscaler for forty-three point nine billion dollars in shares, the biggest cybersecurity deal yet. Nothing changes operationally today: shareholder and regulatory approval are still needed, with closing expected in the second half of CrowdStrike's fiscal twenty twenty-eight.

Both companies are pitching AI security, while the AI-provider investigation has some uncomfortable new detail: OpenRouter's removals were Together AI and Phala, along with Novita; Atlas Cloud withdrew voluntarily. Dragos says none detected the intrusions themselves, and some stolen credentials came from requests rejected before a model ran — a failed request isn't evidence your secret stayed safe. And on AI-assisted intrusions, Wiz reports twenty further disclosed incidents in three weeks, with its own incident-response requests tripling. Its ARTEX-Harvester campaign gives defenders something concrete to hunt: pentest-recon user agents and incrementing task counters in session or resource names. For a quieter bit of automation trouble, Mozilla's advisory replay now reaches back to MFSA 2006-48, through MFSA 2007-01. Extend archive-date suppression to that earlier boundary and check for spurious overnight tickets.

I'd give the APIM credential rotation an owner today, separate from whoever confirms Microsoft's remediation. And I'd ask application owners to search deployed files for that abandoned DLL, rather than trust the patch inventory. Hope Tuesday gives you a clear run at it.
