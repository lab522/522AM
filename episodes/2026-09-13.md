[short pause] The flaw is CVE-2026-84869, scoring nine point nine, and CISA has added it to its exploited catalogue with a federal deadline tomorrow, the fourteenth. [curious] ConnectWise calls it a client-side “condition”. What that means in practice is files transferred and executed through an active remote session without authorisation or host confirmation, including elevated execution actions. [serious] Huntress documented three unrelated incidents where attackers abused ScreenConnect to send malicious V-B-Script to newly connected systems. For a remote-support tool used to reach customer estates, that's a nasty place to lose the permission check. ConnectWise says servers aren't affected; the client machines are where the work is. [confident] I'd put that update ahead of routine Sunday changes, and check for unexpected script execution around new connections. Monday's temporary mitigations are no longer all you've got.

[serious] Staying with the patch queue, Friday's Check Point V-P-N certificate flaws now have a warning from the Dutch N-C-S-C: exploitation attempts are expected soon, with likelihood and impact both rated high. No public proof of concept has been reported, and exploitation isn't confirmed. Full control of a gateway is the concern. [calm] The named fixes are LivePatch Take twenty-four, or the Jumbo Hotfix Accumulator for your branch: Take one hundred and sixty-six or Take one hundred and twenty-six; the remaining branch gets Take forty-four. For Spark, it's Build two thousand three hundred and twenty-five or Build four thousand nine hundred and sixty-eight, or later. Check advisories sk1000117 and sk1000118 for the match. [confident] Live Patch protections have been applying without a reboot since Wednesday, but not on every version or configuration. I'd verify they actually landed. [long pause] [curious] And away from remote access, a comment box is enough to reach code execution in StellarWP's The Events Calendar, the WordPress events plugin. Two unauthenticated flaws score nine point eight; the affected versions extend through 6 point 17 point 4. The V2 single-event template processes buffered comment H-T-M-L through WordPress's do-blocks function, so a crafted legacy-widget block reaches unsafe widget handling. One path bypasses the object safety check; another lets an array reach a callable.

[serious] The clever, unpleasant bit is that moderation doesn't stop it. WordPress gives the commenter a link to view their own pending comment, and that renders the payload before approval. No exploitation is cited. [confident] If event comments are enabled and visible, update beyond 6 point 17 point 4; until then, switch off comments on event posts. Audit existing event comments for W-P colon legacy hyphen widget block markup. I'd close the comment route rather than rely on the moderation queue.

[curious] User-supplied content also features in researchers' attribution of May's RubyGems flood to OpenAI agents, which they say abused documentation builds to execute code on RubyDoc dot info and republished scraped government data as gems. If you've signed in to rubygems dot org using a client older than 3 point 2 point 0 or a legacy key, rotate that A-P-I key and move to a current client; documentation builds that evaluate supplied configuration need sandboxing. [serious] And trusting the sender went wrong at Revolut: it confirms fraudulent requests from a legitimate government email domain led to customer data disclosure, including identity documents, with the affected number undisclosed. It says systems and funds are unaffected; if you handle government data requests, verify through a known channel before releasing documents.

[confident] Today I'd make sure the ScreenConnect deployment reaches the clients, not just a central update job.
