# Cisco's root bypass, N-central's confirmed exploitation

*Cisco's September bundle includes an actively exploited authentication bypass in Identity Services Engine, while N-central's hotfix now has a confirmed exploitation warning and an exact build to check. Also: attacks on Issabel phone systems, Windows domain-trust breakage, and changes to vulnerability feeds.*

[cheerful] Good morning, it's 5:22 AM. Thursday, the seventeenth of September, twenty twenty-six. five twenty-two AM is brought to you by Lab five twenty-two, a technology partner for mid-market businesses, providing cyber security services and enterprise operational software. Email us at hello at lab five twenty-two dot co dot uk if you think we can help your business.

[serious] The box deciding which devices get onto your network has a door that doesn't properly check who's asking. Cisco's September bundle landed yesterday with an actively exploited authentication bypass in Identity Services Engine and I-S-E-PIC, its Passive Identity Connector. CVE-2026-76460 scores ten point zero: a crafted request to an A-P-I endpoint bypasses the web management login, and Cisco warns attackers may get command execution as root. Any configuration from 3 point 1 upwards is exposed. [short pause] CISA added it to the exploited catalogue alongside yesterday's Acronis flaw; both now have a September nineteenth federal remediation deadline. The Cisco entry's the new problem, separate from Tuesday's email gateway story. [confident] I'd put this ahead of routine maintenance. Root on the network's admission desk is quite enough reason.

[calm] For I-S-E, the fixes are 3 point 1 Patch 12 or 3 point 2 Patch 11; on newer branches, 3 point 3 Patch 12, 3 point 4 Patch 7 or 3 point 5 Patch 4. There's no workaround. Infrastructure access control lists can restrict the management plane while you patch. Check every node's ise-kong access dot log for suspicious usernames; Cisco strongly recommends re-imaging suspect nodes, restoring configuration backups if needed. [serious] And the bundle isn't just I-S-E: Cisco says two Management Center flaws are being exploited too, in the console managing the firewall fleet. Every Secure Firewall deployment needs attention: A-S-A goes to 9 point 24 point 1 point 26 or the matching fixed train; Threat Defense and Management Center go to 7 point 7 point 13. Nexus Dashboard 4 point 2 and earlier needs 4 point 3 point 1 point 175. Also check the advisories for ThousandEyes Virtual Appliance before 0 point 265 and BroadWorks CommPilot.

[curious] Another console with a lot behind it: that N-central hotfix we discussed last week now has an exact vulnerability and build to pin to the change ticket. CVE-2026-86218 is static code injection allowing code execution without authentication, rated ten point zero by N-able, and CISA has confirmed exploitation. N-central's the remote management platform that can reach customers' endpoints, so the server isn't the end of the concern. [calm] Self-hosted installations before 2026 point 3 point 1 point 14 need that build, delivered as 2026 point 3 Hotfix 4; hosted instances are already patched. If you can't upgrade immediately, restrict access from untrusted networks, but that isn't a fix. [confident] I'd review appliance logs and administrative activity as a separate job: the hotfix can't tell you whether somebody got there first. Not every publicly discussed N-central compromise has been conclusively tied to this particular flaw.

[serious] And unauthenticated commands are reaching phone systems too: Issabel Framework, the web front end for an Asterisk-based P-B-X, has an actively exploited hard-coded J-W-T signing key flaw, CVE-2026-89026. Apply the latest Framework fixes—the August first patch replaces that shared key—and check internet-reachable installations for calls to slash pbxapi slash manager slash originate. [pause] But applying updates has its own snag today: Microsoft is investigating Windows eleven update K-B five one two four zero zero eight breaking domain trust on some enterprise machines, leaving valid domain credentials unable to log in. There's no official workaround yet, and I'd avoid pushing the community's MachineIdentityIsolation registry change across a fleet: disabling it can itself break trust, with Microsoft's documentation warning that disabling after enforcement requires leaving and rejoining the domain.

[long pause] [curious] Away from the patch queue, check what fills it: CISA's weekly vulnerability bulletin stops on September twenty-eighth as the agency shifts towards risk-based prioritisation. Enable the exploited-catalogue and Cybersecurity Advisories subscriptions in GovDelivery or Granicus before then; CISA also points readers to the CVE catalogue. And yesterday's Mozilla backfill has reached further back, through M-F-S-A twenty twenty-five dash fifteen to dash seventy-three, including Firefox 137 point 0 point 2 and older E-S-R releases. [calm] The batch also extends to Mozilla's iOS browsers and its macOS V-P-N; don't reopen last year's patch tickets just because their advisory pages have arrived today.

[confident] I'd book the management-console changes now, with time reserved afterwards to investigate anything odd in the logs. And if that Windows update's in your pilot ring, check a domain login after the reboot before widening deployment.
